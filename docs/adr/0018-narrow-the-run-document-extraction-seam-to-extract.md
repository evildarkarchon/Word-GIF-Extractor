# Narrow the Extraction run's Document extraction seam to extract

ADR-0016 gave the Extraction run a run-private trait with three methods: whether EPUB cover extraction is configured, the Applicable outcome facts, and `extract`. The first two are read exactly once each, at the top of the run's inner function, and are never asked again. The seam therefore carried two methods for two values fixed before the first document is selected. Both adapters only forwarded them. The production implementation forwarded all three methods to inherent methods of the same names, which is why it had to name `DocumentExtraction` explicitly at every call to avoid recursing into itself. The scripted adapter wrapped a real `DocumentExtraction`, built from a real `ImageWritePolicy` and, where conversion mattered, a real `ConversionPolicy`, solely to forward the two facts back. Of the fourteen run tests that use it, eleven built an Image write policy only to forward its defaults. The seam now covers per-document extraction alone. `run` asks the request's own `DocumentExtraction` for cover intent and the Applicable outcome facts once, and hands both to the inner function as plain values, before the inner function receives anything that can extract.

ADR-0006's paragraph on Applicable outcome facts is not overturned, and this is the part a later reader is most likely to misread. It kept the chain from the Extraction run through Document extraction to the Image write policy, and it rejected caching the two facts when the request is built, because that copy would have to be kept correct by construction. Both still hold. The request retains nothing derived from its policies, Document extraction is still the module that reports the facts, and the Image write policy is still their single owner. What changes is only the transport between `run` and the inner function. ADR-0016's third paragraph treated a value reaching the inner function as that construction-time copy, and that is the step superseded here. The facts are read from their owner at the moment the run begins, both policies are immutable for the run, and the inner function consumes each fact before any document is extracted, so there is nothing a copy could fall out of step with. The rule ADR-0006 recorded about cover intent also stands. Cover intent is classification input rather than an Applicable outcome fact group, so it reaches the inner function as its own parameter and does not ride inside the Applicable outcome facts.

The remaining seam is a closure, `&mut impl FnMut(SelectedDocument) -> DocumentExtractionOutcome`, rather than a one-method trait. ADR-0005 rejected closures for EPUB cover extraction because its two operations both needed a mutable borrow of one EPUB resource archive session, and two closures cannot each capture it mutably. With one operation that objection does not arise. A named trait would keep a doc home for the seam's contract, but it would also keep the forwarding implementation, the recursion workaround that exists only because a trait method and an inherent method share a name, and a trait for one verb. The contract moves to the inner function's doc comment, which already states that every selected document is handed to Document extraction exactly once. The `&mut` and static dispatch match how the run already takes its observer. `FnMut` is the closure form of ADR-0016's `&mut self` reasoning: Document extraction outcomes are not `Clone`, so a scripted adapter hands each one out by value. The seam stays real under the rule ADR-0005 and ADR-0008 apply. Production passes a closure over `DocumentExtraction::extract`, and the run's tests pass one over the scripted adapter. ADR-0016's fifth paragraph placed the trait in the run's module so Document extraction's imports would not name run vocabulary. With no trait, there is nothing left for Document extraction to import.

`RunSelectionInputs` becomes a field of `ExtractionRunRequest`. `run` unpacked the request's four selection fields only to rebuild them into that struct, and the inner function unpacked them again into `DocumentSelectionOptions`: three spellings of four fields. Nested, the struct moves through `run` whole, and the fields are spelled once in the struct and once where selection options are built. Cover intent stays out of it, now because `run` reads it from Document extraction rather than because the seam supplies it. Widening the struct into everything the run was asked, cover intent and Applicable outcome facts included, was rejected. Its only honest name is `Dependencies`-shaped, which ADR-0008 rejected for the two selection seams, and it would put selection input and outcome seed in one value. The inner function therefore takes the selection inputs, cover intent, the Applicable outcome facts, the two selection seams of ADR-0008, the extract closure and the observer. That is seven parameters, each a distinct fact, and every test reaches them through one helper.

The scripted adapter keeps its outcomes keyed by path and its two panics, for a path extracted twice and for a path nobody scripted, but loses its real `DocumentExtraction` and the constructors that bound one to policies. Run tests seed cover intent as a boolean and the Applicable outcome facts through the existing test-only `ApplicableOutcomeFacts::fabricated`. The conversion and Image write policy builders leave the run's tests with them. The four run tests ADR-0017 kept all stay, and only their setup changes. Two of them, that the run's cover intent reaches classification and that the Applicable outcome facts seed the fold, now pin that the inner function routes its own parameters to selection, to the extraction-started observation and to the accumulator, which is still the run's job. The test that checked the scripted adapter forwarded the two facts is deleted with the forwarding. Its assertions move down to Document extraction's tests as a direct test of what `DocumentExtraction` reports from real policies. That report had no other test: the GIF destination half of it was checked only through the scripted adapter's wrapper. The change is strictly behaviour-preserving. The observation stream, the outcome, the files written, the command-line output and the `tests/` suite are unchanged, and a moved test whose assertion has to change is evidence of a behaviour change, not a test to fix.

Out of scope:
- the Image write pipeline's forwarders for the two facts, and whether the Image write policy's own accessors can become private to the pipeline;
- having `DocumentExtraction::new` take an Image write policy, to remove the pipeline wrapping repeated at its call sites;
- the GIF destination's lack of any end-to-end check, which predates this change.

`CONTEXT.md` does not change. Its Applicable outcome facts entry says Document extraction reports them from the Image write policy at the moment an Extraction run needs them, and that is still true. Nothing here becomes public: ADR-0003 still governs the library interface, and every item this change touches stays crate-private or narrower. This decision is recorded ahead of the change it governs, in the manner of ADR-0006, ADR-0007, ADR-0008, ADR-0016 and ADR-0017, and 0015 stays vacant for the reason ADR-0016 gives. ADR-0016's first, third and fifth paragraphs receive status notes pointing here when the code lands, not before, so no ADR describes a design the code does not yet have. ADR-0006 receives none, because none of its decisions change.
