# Collapse the observation vocabulary into one stream

Document selection emits Extraction run observations directly. The separate Document selection progress and diagnostic types, the `DocumentSelectionObserver` trait, and the run-private adapter that rewrapped one vocabulary into the other are gone, because the Extraction run never inspected the values it was transporting: its adapter's two methods did nothing but wrap A in B, while Extraction run presentation imported six Document selection types and matched them four levels deep. Twenty variants across six types now read as fifteen variants in one, and the seam a fact crosses no longer depends on which module produced it.

The new `extraction_run_observation` module owns the outcome types — `ExtractionRunOutcome`, `ExtractionOutputKind`, `ProducedOutput`, `ConversionFacts` and `GifRoutingFacts` — as well as the observation enum and its observer. Leaving them in the Extraction run was considered and rejected: `ExtractionRunObservation::Terminal` carries an outcome, so the observation module would have depended on the Extraction run while Document selection depended on the observation module and the Extraction run already depended on Document selection. Rust permits that cycle inside one crate, but it would have reintroduced exactly the mutual dependency the new module exists to remove. With the outcome types here, Document selection, the Extraction run and Extraction run presentation all depend on this module and it depends on none of them. Its one outward edge is `DocumentExtractionWarning`, which does not come back because Document extraction never observes a run.

Two smaller decisions follow from the same rule that observations carry structured facts rather than policy or wording. The EPUB filtering variants carry the requested title and author instead of the Document selection `EpubFilter` that holds them, which keeps a selection policy type off the stream and out of this module's dependencies; carrying `EpubFilter` itself, relocating it here, and giving it its own module were all considered and rejected as either wrong-homed or disproportionate for a two-field struct. Separately, each phase now has a running variant and a finished variant instead of one variant carrying a `DocumentSelectionPhaseStatus`, so "exactly one finished snapshot per phase" is visible in the type rather than stated only in a doc comment. That costs three variants and removes a type, a field, and one level from every consumer's match.

The phase lifecycle itself was deliberately left alone. `DocumentSelectionLifecycle` and its three phase reporters keep their shape, counters and assertions; only the observations they construct changed, and the discovery phase took the glossary's Document discovery vocabulary in place of the scan synonym `CONTEXT.md` tells us to avoid. The three byte-identical `diagnostic` bodies they still contain are known duplication and a separate change.

One compile-time guarantee was traded away and is recorded here rather than left for a reader to discover. The lifecycle's `diagnostic` methods took a `DocumentSelectionDiagnostic`, so only a diagnostic could be passed; they now take an `ExtractionRunObservation`, so `lifecycle.diagnostic(ExtractionRunObservation::Terminal(..))` type-checks. Keeping the narrow parameter would have meant keeping a second selection-owned enum purely to constrain one internal call, which is the duplication this ADR exists to remove. The exposure is bounded: the methods are `pub(super)` inside Document selection, every call site passes a diagnostic variant, and the phase-ordering tests would fail if one did not. If a wider guard is ever wanted, the honest form is a diagnostic-only constructor on the observation module rather than a restored parallel vocabulary.
