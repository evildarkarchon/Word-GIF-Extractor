# Put Document selection's ambient dependencies behind two seams

Document discovery reaches the world through six inline sites — `fs::metadata` three times, `fs::symlink_metadata` once, `fs::read_dir` once, and one `WalkDir` traversal — and Document selection acquires EPUB declarations through `EpubDeclarations::acquire`, which opens the file with `EpubDoc::new`. Both move behind crate-private `&dyn` traits with a real adapter in production and an in-memory adapter in tests. The first is the Document search surface, a new `CONTEXT.md` term naming what Document discovery can observe about the world it searches: what one path is with links followed, what it is without, what one directory directly contains, and what a recursive traversal of one directory yields in encounter order. The second covers declaration acquisition and nothing else. They arrive as two separate parameters on `select_documents` rather than one bundle, because the only honest names for a bundle of both are `Dependencies`-shaped and say nothing about what is inside, and separate parameters keep the same import-legibility rule ADR-0004 and ADR-0005 both turn on. Neither belongs in `DocumentSelectionOptions`, which carries per-run policy — the inputs, the recursion flag, the output directory and the EPUB filter — and a way of seeing the world is not a policy choice.

The crate keeps four other direct `std::fs` call sites, in the DOCX adapter, the EPUB resource archive, and Image file emission, and leaving them alone is a decision rather than an unfinished sweep. Document discovery is the only one whose result is *determined* by what it observes: which paths exist, what kind each is, and what a directory holds are its entire output, so substituting the observation substitutes the whole answer. The others act on a path some earlier decision already named, and their tests want real bytes regardless — a ZIP the `zip` crate can open, an image the `image` crate can decode, a file that visibly appears on disk when Image file emission claims a collision-free name. Abstracting those would buy a fake where a real file is cheaper and tells the truth about more of the stack.

The traversal vocabulary is owned by this crate rather than borrowed from `walkdir`, and this is the part most likely to look like gratuitous indirection to a later reader. It is not a preference: `walkdir::Error`, `std::fs::Metadata` and `std::fs::DirEntry` have no public constructors, so an in-memory adapter cannot produce any of them. Passing walkdir's own `Result<DirEntry, walkdir::Error>` across the seam would leave exactly the failure cases this change exists to make testable permanently unreachable from a test. The surface therefore yields an entry carrying its path, its depth and whether it is a directory, and a failure carrying its depth, an optional path and an `io::Error`; the traversal itself keeps a `skip_current_dir` operation, so it is an object with mutable state rather than a function returning a list. Depth on both the entry and the failure is load-bearing: Document discovery indexes known directories by depth so that a truncated traversal can attribute an error with no path of its own to the nearest confirmed parent.

Failures cross the seam as `io::Error` rather than as an owned failure value, because Document discovery branches on `ErrorKind::NotFound` to tell a genuinely absent path from a link whose target is gone, and `io::Error::new` lets an in-memory adapter produce that distinction directly. The cost is that the `detail` string on a Document selection diagnostic is now adapter-dependent — an in-memory adapter's wording is not the operating system's — so diagnostics are asserted by the path they name and the fact that they were emitted, never by their message text.

Requested-input classification stays in front of the seam. The two-step lookup — `metadata`, and only on a not-found result a second non-following lookup — is precisely the production behaviour this change exists to make testable, so it cannot live inside the thing being substituted. Putting a single `classify` operation on the surface instead was considered and rejected twice over: it would move the branch into adapter code where the in-memory version cannot exercise it and the real version is covered only by the conformance tests below, and a faithful in-memory adapter would then have to reimplement the same two-step dance over its own tree, leaving the logic written twice with the tests exercising the copy.

Directory listing and recursive traversal stay two operations on the surface. Both branches of Document discovery already re-inspect every entry they encounter, so their link-following behaviour may in fact coincide, and a single depth-bounded traversal would delete the whole non-recursive arm. But "may coincide" is an untested claim about symlink handling, and unifying them inside the change that introduces the seam would land a refactor and a behaviour change together with no test able to tell them apart. Confirming or refuting that claim is the follow-up this change unlocks, and it is deliberately not attempted here.

ADR-0005 ruled that one adapter makes a seam hypothetical and two make it real, and it answered its own case by counting the test adapter as the second implementation — because `ArchiveResourceIdentity` is obtainable only by opening a real archive, so a concrete identity would force every cover-ordering test to write a ZIP to observe a decision that never touches disk. The declaration seam is that argument again, unchanged. Four Document selection tests currently build real EPUB archives in temporary directories to assert filtering, deduplication and display-name derivation, none of which reads a byte of payload. What the seam does *not* buy is the deletion of `test_support.rs`'s OPF and ZIP builders: those are the shared core of every EPUB fixture in the crate and are called from four other test modules, so they stay. Six call sites in Document selection's tests go away, and that plus the paragraph below is the whole case — a later reader should not measure this seam against a larger claim.

ADR-0001 and ADR-0002 survive intact, and the seam is drawn to make that checkable rather than merely intended. It substitutes *how* declarations are acquired, never *when* or *how often*: ADR-0001 keeps declaration acquisition separate from incremental payload reads, and ADR-0002 makes a retained declaration authoritative for the Extraction run, with Document extraction reacquiring only when selection could not. That last sentence has never been tested, because the skipped reacquisition is invisible to any assertion. An in-memory declaration adapter records which path it was asked for and in which phase, which turns ADR-0002's rule into something a future change breaks loudly. Asserting the observable consequence instead — that a candidate with retained declarations produces no unreadable-metadata diagnostic during deduplication even when its file has been made unreadable — was rejected as requiring the mid-run permission change the suite has never managed to stage on Windows. Document extraction's own reacquisition site is deliberately left on the concrete call: it opens a real archive for payloads under ADR-0001 in any case, so a seam there would abstract one of two operations on the same file and buy nothing.

Of the thirty-three Document selection tests, twenty-one stage real disk state today. Five real-filesystem tests survive, and they move to sit beside the real adapter rather than staying in Document selection's tests, because their subject is that the real adapter agrees with `std::fs` and not that selection selects correctly: a broken requested link reports an inspection failure rather than a missing input, a genuinely absent path reports a missing input, a requested directory link is followed when recursive, a nested directory link is not, and a nested file link remains eligible. The inspectable-but-unsupported object — a fifo or a socket — is not among them and is covered in memory only, because it cannot be staged portably on Windows. The observer-as-filesystem-hook used by the three race tests, which deletes the search root from inside the progress callback on the first discovery observation, is deleted: a stale entry becomes a value the in-memory adapter returns, and the three `skip_current_dir` branches it was reaching get direct tests for the first time.

Nothing here becomes public. ADR-0003 still governs the library interface; both traits, both real adapters and the traversal vocabulary stay crate-private, and the in-memory adapters live in the crate's test support. This decision is recorded ahead of the change it governs, in the manner of ADR-0006 and ADR-0007. The change lands in three further commits: the Document search surface and its real adapter, with every existing assertion untouched and each call site gaining only the added argument, so that a failure there is the seam and not a moved test; then the in-memory adapter and the test conversion; then the declaration seam and the ADR-0002 call-discipline tests. `CONTEXT.md` gains its Document search surface entry once the surface exists rather than with this ADR, because a glossary should not define a term the crate does not yet have.
