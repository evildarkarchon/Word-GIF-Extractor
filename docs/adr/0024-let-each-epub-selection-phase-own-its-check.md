# Let each EPUB selection phase own its check

This supersedes ADR-0012's split of each EPUB phase into a loop and a per-EPUB check closure, and the reconciliation note ADR-0012 carries about the `EpubDeclarationDiagnostics` handle. ADR-0012's other decisions stand. The phase derives its total from the EPUBs it was given, an empty phase emits nothing, each EPUB is recorded exactly once, and the completeness assertions stay deleted. ADR-0019 set this change aside only because it reopens ADR-0012, and ADR-0012 has since expired.

Today the progress module runs the EPUB filtering and deduplication loops, and the decisions those loops exist for sit in closures in `document_selection.rs`: the filter match, ADR-0002's reuse of retained declarations, and the dedupe-key set. To keep the two apart, the module lends callers a protocol nearly as large as the loop it hides. That protocol is a closure shape, `FnMut(EpubCandidate, &mut EpubDeclarationDiagnostics) -> Check`, plus two outcome enums, `EpubFilterCheck` and `EpubDeduplicationCheck`, plus a diagnostics handle, plus the rule that diagnostics precede the running observation. The barrier stopped the decision from recording its own progress. Once the decision is written inside the loop it reports into, the decision and the loop are the same code, and the barrier protects nothing.

Each EPUB phase is now one `DocumentSelectionLifecycle` method that does its whole job: `filtering(&EpubFilter, epubs, &dyn EpubDeclarationSource)` and `deduplicating(epubs, &dyn EpubDeclarationSource)`. Each method acquires declarations, or reuses retained ones through `EpubDeclarations::retained_or_acquire`. It makes the filter match or the dedupe-key decision, emits the unreadable-declarations diagnostic, and emits its running and finished progress. `filtering` builds its own `EpubFilterTerms`, and `deduplicating` keeps its own `seen` set. `filtering` takes the raw `EpubFilter`, not only the terms, because its observation reports the user's spelling rather than the case-folded terms. An empty filter returns the EPUBs unchanged and emits nothing, so the filtering phase owns its whole activation rule: active exactly when a filter is requested and at least one EPUB was found. The check enums, the diagnostics handle, `filter_epub_files` and `deduplicate_epubs_by_declarations` are deleted, and `select_documents` calls the phases directly. The phases sit on the lifecycle rather than in free functions so that the lifecycle stays the sole emitter of Document selection observations, with one method per fact as ADR-0009 made it. A free function would need fine-grained emit methods such as `epub_checked`, and those would bring back the risk ADR-0012 removed: an EPUB recorded twice or not at all. The module is renamed from `progress` to `phases`, because it now holds the decisions as well as their progress.

The two phases keep separate concrete loops. A shared generic loop would need the decision passed in as a closure, which is the protocol this change deletes, and the two phases differ in their counters and observation variants. Fusing them into one pass that filters and dedupes each EPUB was rejected, because it would interleave `FilteringEpubs` and `DeduplicatingEpubs` observations and change the stream.

Two guarantees ADR-0009 placed in types become guarantees of the code's shape:
- **Observation order.** "Each EPUB recorded once, its diagnostics ahead of the running observation that records it" now holds because one loop body is written that way, not because the decision cannot reach the observer. The characterization tests that pin both phases' diagnostics ahead of their running observation are now the enforcement.
- **Declaration purpose.** Each phase writes `EpubDeclarationPurpose` as a literal at its single emission site. A wrong literal is caught by the tests that pin each phase's purpose, not by the compiler. A private helper taking the purpose as a parameter was rejected, because it would guard nothing.

ADR-0009's silence gate for Document discovery, `emit_when`, is replaced by an early return. `discover_documents` returns nothing when no input was requested. That is the only case in which discovery was inactive, and it is unreachable from the command line, because Extraction run intake defaults to the current directory. The `active` parameter of `discovering` and the `active` field of `DocumentDiscoveryProgress` are deleted with the gate. Discovery now follows the EPUB phases' rule that an empty phase emits nothing. Deleting the gate without the early return was rejected, because empty inputs would then report an empty discovery phase. Discovery keeps its body-closure shape for the reason ADR-0012 gives: it has no known total, and forcing its walk into a per-item closure would cost more interface than it saved.

The change is strictly behaviour-preserving. The observation stream, the Selected documents and their order, the files written, and the command-line output are all unchanged. A `select_documents` test whose assertion has to change, including the test that a run requesting no input stays silent, is evidence of a behaviour change, not a test to fix. The glossary is unchanged: Document selection progress and Document selection diagnostic describe what the user observes, and none of that moves. Letting Extraction run presentation trust the selection lifecycle is out of scope and left for a change of its own. Nothing here becomes public: ADR-0003 still governs the library interface, and every item this change touches stays private to Document selection. This decision is recorded ahead of the change it governs, in the manner of ADR-0019.
