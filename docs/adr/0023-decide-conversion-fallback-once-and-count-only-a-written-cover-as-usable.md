# Decide conversion fallback once, and count only a written cover as usable

A user who runs `--cover-only --cover-fallback` expects one of two things from every EPUB: its cover, or, when it has no usable cover, its normal images. Today some EPUBs give neither, with nothing beyond a warning to say why:
- When `--formats` filters out the declared cover's Image format, the cover is skipped, the filename cover candidate is never tried, and fallback does not run. The EPUB writes nothing.
- When a cover's conversion is unsupported, such as an SVG cover with `--convert png`, or fails on a payload that cannot be decoded, the cover is not written at all. A normal image in exactly the same situation is written in its original bytes. Again the filename candidate and fallback are skipped.

The README promises that "an EPUB with no usable cover falls back to extracting its images". The code means something narrower by "no usable cover": only that no cover candidate could be read. A required-cover attempt returns a fact-free `RequiredCoverDisposition`, retry or completed, beside its facts, and completed covers a cover that was written, a cover that was filtered out and a cover whose conversion fell back. EPUB cover extraction stops on completed, so the last two end the cover search having written nothing.

A maintainer meets the same split from the inside. What a conversion fallback means is decided twice in the Image write pipeline, once in each visitor's match on the preparation result. The normal-image visitor writes the original bytes and the required-cover attempt writes nothing. The Image write purpose is spelled into four warning variants: `ConversionSkipped` and `CoverConversionSkipped`, `ConversionFailed` and `CoverConversionFailed`. The tests that drive image preparation directly cannot reach either decision, because it is made after preparation returns. Normal-image conversion warnings also name the Output placement's base name rather than the image, so two failing images in one document produce two identical warnings. The rule that a required cover is never written in bytes the Conversion policy could not produce appeared only in a code comment, never in an ADR or the README. Reversing it therefore contradicts no recorded decision.

Four decisions follow.

**Conversion fallback no longer depends on the Image write purpose.** Image preparation resolves a conversion that cannot produce the requested bytes once, for every source. Whether the conversion was unsupported or failed, the original bytes are emitted under their original Image format, with the conversion-skipped Emitted image role and one warning fact. A cover is now written in its original bytes in exactly the cases a normal image is. The separate fallback case of the preparation result is deleted, and so are both visitors' matches on it. Preparation returns a prepared image, alone or with its conversion warning, and each visitor stages what it gets back. The exact shape of that return is left to the implementation. The required-cover path records a conversion-skipped image through ADR-0017's `record_cover`, so the Emitted image tally counts it as a conversion-skipped cover, and the terminal summary's conversion-skipped count matches the files on disk.

**A usable cover is a cover file that was written.** The required-cover scope exposes one query: has this scope written a cover? It answers from its own folded Emitted image tally, as covers recorded greater than zero, so the answer can never disagree with the facts the scope returns. EPUB cover extraction keeps the candidate order it has today, the declared cover and then the filename cover, and skips every Archive resource identity already attempted. It attempts each candidate and stops as soon as the scope reports a written cover. A candidate that writes nothing hands over to the next one, and so does one whose format was filtered out, one whose payload could not be read and one that is missing. When the candidates run out without a written cover, a `CoverThenNormalImages` policy falls back to normal images, still excluding every attempted identity, and a `CoverOnly` policy ends with no output. With `--cover-fallback`, an EPUB therefore falls back exactly when no cover was written, whatever the reason. A written cover ends the search whether it was converted, kept in its original bytes or routed to the GIF destination, so one EPUB never yields two covers. The warnings of a candidate that was passed over still come first, because the scope folds facts in the order they happened, and a filtered cover keeps its "not in allowed formats" warning even when a later candidate or fallback succeeds. An emission failure still ends the sequence as an error that carries every earlier fact. Candidate order, identity exclusion, hand-over and the fallback decision stay in EPUB cover extraction. The scope still folds facts, and EPUB cover extraction still never combines them.

**Conversion warnings name the source image.** `ConversionSkipped` and `ConversionFailed` stay. `CoverConversionSkipped` and `CoverConversionFailed` are deleted. Both remaining variants identify the image by the source's diagnostic name, the name `ArchiveImageAcquisitionFailed` and `ExtensionFallback` already use, in place of the Output placement's base name. Document extraction's stable wording changes to match. The normal-image wording names the source image instead of the document, and the cover-only wordings "…skipping cover." and "Cover conversion failed: …" are removed, so cover and normal-image warnings read the same way. The normal-image visitor stops holding a copy of the Output placement beside its Image file emission, since the copy existed only to put the base name into warnings. Image file emission alone keeps the placement, as ADR-0022 decided.

**The required-cover disposition is deleted.** The scope's attempt and unreadable operations no longer return a disposition, and `RequiredCoverDisposition` is deleted. Each operation records its facts into the scope and returns only an emission error. Whether to go on is the scope's written-cover query, so cover attempts no longer hand back a second channel beside their facts.

ADR-0021 is amended, not superseded. Its description of the required-cover scope's attempt and unreadable operations no longer holds. The attempt returned a fact-free `RequiredCoverDisposition`, retry or completed, and unreadable always meant retry. Both now return nothing beyond an emission error, and EPUB cover extraction asks the scope whether it has written a cover. The rest of ADR-0021 stands. EPUB cover extraction stays one concrete function over the real session and the real pipeline. The scope's fallback operation still runs a fresh normal-image visitor and appends its facts after the cover attempts' facts. The rejection of typestate still holds. ADR-0021 receives a note pointing here when the code that deletes the disposition lands, not before, so no ADR describes a design the code does not yet have. ADR-0021 gave ADR-0005 the same treatment.

The decisions that stay binding, and why this does not reopen them:
- ADR-0017's `record_normal_image` and `record_cover` are unchanged, and each call site still knows its purpose at compile time. The tally's role mapping still counts in one place.
- ADR-0018's narrow Document extraction seam is unchanged. The summary's covers-only classification already reads the Emitted image tally, so an EPUB that fell back is classified as having produced normal images with no new logic.
- ADR-0020's purpose carried on the archive image source is unchanged, and so are the two rules Archive image discovery decides by it: an unidentified required cover is written as JPEG with a warning, and a filtered required cover warns while a filtered normal image completes silently. After this change those two rules are the only places the Image write purpose changes behaviour, apart from the side of the tally an image is recorded under.
- ADR-0022 is unchanged. A required-cover attempt still creates one Image file emission, stages its single prepared image and finishes. Fallback still runs only when no cover was written, and it still gets a fresh Image file emission. The two visitors stay two. This decision moves one rule out of both of them and does not merge their per-image paths, which ADR-0022 left out of scope.

Three alternatives were rejected:
- Keeping the disposition and adding a third variant for "wrote nothing". The written-cover question would then be answered twice, by the disposition and by the facts beside it, and the two could disagree. The tally already knows the answer.
- Handing over only from a filtered candidate and keeping the "never write unconvertible cover bytes" rule. A cover whose conversion fell back would still be dropped while an identical normal image is kept, and a user would have to know which internal case stopped the cover to predict the outcome.
- Purpose-specific warning variants with the source name added. That would keep the Image write purpose spelled into the warning vocabulary for no difference the user can observe.

Open question. An unidentified payload behind the declared cover is still written as JPEG with a warning, under ADR-0020's discovery rule. It is therefore a written cover and still ends the search, even when the filename cover candidate would have given a real image. Whether an unidentified cover should hand over to the next candidate instead, or stop defaulting to JPEG, is left open. Changing it changes which file a user receives, so it is a decision of its own.

Out of scope:
- Changing the unidentified-cover JPEG default, as above.
- Binding the Image write pipeline to one Output placement per document, and deleting its policy forwarders.
- The GIF destination's two routes to the Extraction run outcome, which ADR-0017, ADR-0018 and ADR-0022 govern.
- Document selection, Document identity, and which documents a cover run selects, which ADR-0011 governs.
- Cover candidates beyond the declared cover and the filename cover, or a different order.
- Warning wording other than the two conversion warnings.

The glossary and README changes land with this ADR rather than with the code, following ADR-0017. The EPUB cover policy and EPUB cover extraction entries define a usable cover as a written cover, and the latter replaces "one required-cover outcome" with hand-over and fallback. The Image write purpose entry says the purpose changes behaviour only in Archive image discovery. The Image write pipeline and Conversion policy entries say that a conversion fallback emits original bytes whatever the Image write purpose. The README's `--cover-fallback` description says a cover filtered out by `--formats` counts as no usable cover, and its Conversion section says an image that cannot be converted, a cover included, is kept in its original format. Nothing here becomes public: ADR-0003 still governs the library interface, and every item this change touches stays crate-private or narrower. This decision is recorded ahead of the change it governs, in the manner of ADR-0017 through ADR-0022, and 0015 stays vacant for the reason ADR-0016 gives.
