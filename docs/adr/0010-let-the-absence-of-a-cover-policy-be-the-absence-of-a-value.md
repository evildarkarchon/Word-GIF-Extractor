# Let the absence of a cover policy be the absence of a value

> **Superseded in part by ADR-0011.** The decision recorded here — cover intent as
> `Option<EpubCoverPolicy>`, reaching only the EPUB arm — stands. The fifth paragraph
> below is wrong: it treats "a cover-only run still emits a DOCX's normal images" as
> intended behaviour worth re-pinning, when that was the bug the option shape existed
> to make fixable. `--cover-only` now selects EPUB documents only.

`DocumentExtractionPolicy` had two variants, `NormalImages` and `EpubCover { fallback_to_normal_images }`, and one of them named an absence. A run that wanted normal images was not a run without a cover decision; it was a run carrying a value that said "no cover decision", and that value was as handable as any other. It got handed: `DocumentExtraction` stored it as a field and the dispatch passed it only to the EPUB arm, so the DOCX arm dropped a per-run user choice on the floor with no warning and no diagnostic. Nothing in the type objected, because there was always something to drop. The type is replaced by `EpubCoverPolicy` with variants `CoverOnly` and `CoverThenNormalImages`, carried as `Option<EpubCoverPolicy>`. `None` is the request for normal images. The DOCX arm cannot drop a cover policy because in a normal-images run there is no value, and in a cover run the value never travels down that arm.

The three-variant alternative — keep one enum, add no `Option`, and simply not pass it to DOCX — was rejected, and it is worth being precise about why, because it is what the code did. It is the same runtime behaviour. What it cannot do is make the omission visible: a reader of the dispatch sees a value in scope and one arm that ignores it, and has to know that ignoring it is correct. Under the `Option`, the EPUB arm's exclusive access to cover intent is the only shape the code can take. This follows ADR-0007's rule one level up: a value should mean one thing, and a variant that means "this value does not apply" means the value applies everywhere and matters somewhere.

The re-typing runs all the way to Extraction run intake rather than stopping at `DocumentExtraction`. Narrowing at the bottom was considered and rejected: it would leave both types alive permanently and keep `NormalImages` — the variant whose whole problem is the absence it names — in the two modules above the one that fixed it. Intake is also where the `Option` is most natural, since `cover_only == false` maps to `None` with no intermediate. The cost is a wide commit: twenty-three construction sites across two test files, all mechanical.

Two boundaries do not move. `is_epub_cover_extraction_configured` keeps its name and becomes `self.cover_policy.is_some()`, because the Extraction run still needs cover intent to classify its outcome — CONTEXT.md's Applicable outcome facts entry says cover intent reaches the outcome at classification time, and that path is unchanged. And ADR-0005:7 recorded that EPUB cover extraction takes a plain boolean for fallback rather than a Document extraction type, so its imports answer what cover extraction depends on; that still holds, so `epub::extract` flattens `CoverThenNormalImages` to a bool at the call. Readers of ADR-0005 should note that the "Document extraction policy" it names is this type under its former name — the argument it makes is unaffected by the rename.

One test is deleted and one is added, and they are not the same test at a different address. `docx_uses_normal_images_when_policy_requests_an_epub_cover` asserted that a cover policy handed to a DOCX was dropped; it is now unconstructible, and the fact it asserted is structural. But it was also the only test in the crate holding up a user-visible claim: that a cover-only run does not silence a document kind without covers. That claim is now pinned at run level by `docx_in_a_cover_only_run_still_emits_its_normal_images`, the crate's first mixed-kind multi-document run test. Trading a behavioural assertion for a structural one without replacement would have been a real loss; trading it for one asked at the level where a user would notice is not.

Nothing here becomes public. ADR-0003 still governs the library interface: `EpubCoverPolicy` is `pub(crate)`, exactly as `DocumentExtractionPolicy` was.
