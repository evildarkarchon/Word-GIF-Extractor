# Recognize a duplicate EPUB by identifier, creator and title, and name every skip

The 2026-11-14 audit (H2) showed EPUB deduplication dropping books that were not duplicates, silently. The key was the case-folded creator and title, with an absent half read as the empty string, and an EPUB that declared neither was keyed on its file name alone. So every issue of a periodical after the first was dropped, because issues share one creator and title. Every title-less book by one author collapsed into one. Two undeclared `book.epub` files in different directories were taken for one book. The only trace was a count on the progress display, which named no file. That count is invisible when standard error is redirected (H3), and the run exited 0.

Duplicate recognition now keys on three declarations: the package's unique identifier, the creator and the title, each trimmed and case-folded. The identifier is the `<dc:identifier>` that the package's `unique-identifier` attribute names, which the `epub` crate already resolves. `EpubDeclarations` carries it, and Document identity asks for it as a parameter, because naming, display and filtering never read it. An EPUB has a key only when it declares an identifier, or when it declares both a creator and a title. An EPUB with neither, including one whose declarations cannot be read, has no key. It is never taken for a duplicate, and no later EPUB is taken for one of it.

The identifier separates the issues of a serial, and true copies share it. The creator and title stay in the key beside it, rather than the identifier deciding alone. A placeholder identifier, or an ISBN reused across the volumes of a set, would otherwise merge different books, and of the two possible mistakes, keeping a copy costs a few extra images while dropping a book loses it. So a copy whose identifier was stripped, or whose title was re-edited, is kept rather than recognized. One declaration by itself never makes a key, since a creator alone names an author's whole shelf. A file name is never a key. Two sightings of one path are already one candidate under ADR-0019, so the only thing a file-name key ever added was a collision between different files.

Each skipped EPUB is reported as its own Document selection diagnostic, `SkippedDuplicateEpub { path, duplicate_of }`, in the style ADR-0009 set. Both paths travel, so the user can see which copy was kept. Unlike `SkippedNonEpubInput`, it is reported for an EPUB found by a directory search too: skipping a duplicate is a decision about the user's documents rather than about which inputs were eligible. Following ADR-0024, it precedes the running observation that counts the skip. Presentation renders it as a warning that names `--keep-duplicates`. It does not change the exit status, as with the other selection diagnostics (ADR-0014).

`--keep-duplicates` turns recognition off. The deduplication phase still runs and keeps ADR-0024's activation rule, active exactly when there is an EPUB, because it is where an EPUB that no filter read acquires the declarations its Document identity is built from. Skipping the phase would rename that EPUB's output after its file. Under the flag no EPUB has a key, so every EPUB is kept and none is reported. `deduplicating` takes the flag as a third parameter. This extends ADR-0024's signature rather than contradicting it: the phase still owns its whole check.

This changes behaviour on purpose. EPUBs that used to be dropped are now selected, and a run with a true duplicate now writes a warning. ADR-0019 is untouched: it governs repeat sightings of one path and the join order, not recognizing two files as one book.
