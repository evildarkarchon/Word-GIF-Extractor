# Make the emitted-image role a closed value

`PreparedImage` carried `routed_gif`, `converted` and `skipped_conversion` as three independent booleans, so eight states were representable where the Image write pipeline can produce four. Those three fields become one `EmittedImageRole` with variants `RoutedGif`, `Converted`, `ConversionSkipped` and `Preserved`, and the routed variant carries the GIF destination borrowed from the Image write policy. `emit_prepared_image` matches the role once for the destination and once for the counts instead of testing three flags, and `expect("routed GIF should have a configured destination")` is gone: preparation could only mark routing after reading `gif_output`, and the destination now travels with the decision that read it rather than being fetched a second time.

The `debug_assert!` in `DocumentExtractionFacts::from_image_write_result` stays, and the reason it stays is not the reason ADR-0006 gave for putting it there. ADR-0006 enforced the partition at that seam because the routed and converted sets were disjoint only through a control-flow decision — an early return for routed GIFs — and nothing in the pipeline stated it. The pipeline states it now, in the type, so every result the pipeline produces satisfies the rule by construction and the assertion can no longer fire on a production path. What it still guards is `ImageWriteResult::new`, which validates nothing and is how a caller assembles a complete outcome from already-produced facts. The assertion therefore keeps its placement and changes its job: it was a tripwire for a conversion change breaking an unstated invariant, and it is now a tripwire for a fabricated result reaching Document extraction. Deleting it was considered and rejected on exactly that ground.

Locking `ImageWriteCounts` down so counts could only be folded from roles was considered and rejected, and the rejection is about ADR-0005 rather than about effort. The four fields are read at roughly ninety sites, nearly all test assertions, and hand-built `ImageWriteCounts` literals appear five times in the EPUB cover extraction tests, where `CannedAttempts` fabricates Image write facts precisely so cover ordering, exclusion and retry can be asserted without opening a real EPUB. Making the counts constructible only from roles would tax that seam — the one place in the crate where a policy decision is tested without touching the filesystem — to close a hole no production caller can reach. The counts stay as they are and the assertion above covers the gap.

Three smaller decisions follow the rule that a value should mean one thing. The role has four variants rather than five: an image reaches `Preserved` both when no Conversion policy was requested and when conversion preserved a matching source, and nothing counts or renders that difference, while the warning facts already carry the explanation where a user needs one. `format` stays a sibling field rather than moving into each variant, because every role has exactly one format and moving it would re-spell the field four times to express nothing the sibling does not already guarantee. And the routed destination is borrowed from the Image write policy rather than cloned into the variant: the policy is immutable for the Extraction run and outlives every staged image, so the borrow costs a lifetime parameter on a module-private struct and saves a `PathBuf` clone per routed GIF.

Two things are deliberately out of scope. `prepare_image_for_write` returns an `Option` because a required cover can decline emission and a normal batch image cannot, which forces `unreachable!("normal-image preparation always preserves accepted bytes")` on the normal path; that shape belongs to the Image write purpose trait and is not touched here. Nor does this change add tests. The role partition is a property of the type rather than a runtime condition, the existing cases already pin every role the pipeline's own fixtures can reach, and a suite that stays green and unchanged is the evidence that the change preserves behaviour.

This decision is recorded ahead of the change it governs, in the manner of ADR-0006. Nothing here becomes public: ADR-0003 still governs the library interface, `EmittedImageRole` and `PreparedImage` stay private to the Image write pipeline module, and no item outside it changes shape.
