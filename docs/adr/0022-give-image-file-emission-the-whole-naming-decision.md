# Give Image file emission the whole naming decision

A maintainer who wants to know what the Image write pipeline will call a file has to piece one rule together from four places in two modules. A lone image is named after the Output placement's base name and several are numbered, so the normal-image visitor holds its first prepared image back until a second arrives or the traversal ends. That wait is `NormalImageNaming`, a three-state machine (undecided, one image pending, numbering) that sits beside the visitor's discovery, conversion and fact bookkeeping. A required-cover attempt builds an `ImageFileEmission` with `OutputNaming::Singular` itself, restating a rule the visitor already decides by lookahead. `emit_prepared_image` chooses each file's directory from its Emitted image role, the GIF destination for a routed GIF and the Output placement's directory for everything else, and hands that directory to Image file emission on every image. Image file emission holds only the tail of the rule. It owns the ordinal and the collision suffix, but it takes its singular-or-numbered mode from its caller and is passed the output directory per image, although its base name is fixed when it is built. The glossary already assigns this work to Image file emission: its Output placement entry excludes "collision handling and per-image naming, which belong to Image file emission". The code does not match. The README's rule that a routed GIF keeps its place in the count is pinned only through `write_from`, by a test that also exercises discovery, preparation and routing, and no test drives Image file emission's own interface at all.

Image file emission becomes the Image write pipeline's single owner of naming and placement for one pipeline invocation under one Output placement. It decides:
- whether names are singular or numbered, by its own lookahead;
- each image's ordinal across every image the invocation emits, GIF-routed images included;
- the directory each image's Emitted image role sends it to;
- creating that directory before each file is written;
- a collision-free name, claimed without overwriting existing output, and the completed file.

It has three operations, all private to the pipeline:
- create, from one Output placement, which binds the output directory and base name for the instance's lifetime;
- stage, which takes one prepared image and a recording callback, and may write nothing, because the image is held back until singular-versus-numbered naming is known, or may write the held-back image and this one;
- finish, which consumes the instance with a recording callback, writes a still-held-back image under the singular name, and writes nothing and creates no directory if nothing was staged.

The callback is invoked once per completed file, in completion order, with that file's Emitted image role, and only after the file is fully written. A held-back first image written when the second arrives is therefore recorded even if the second then fails, so partial facts are never lost. Directory creation, collision exhaustion, create, write and flush failures are returned with the same context wording as today, and files completed before the failure have already been recorded. An Image file emission that returned an error must be dropped. That contract is documented where the type is defined, not enforced by it, and both callers already abort on the error. The singular-or-numbered mode, the ordinal counter, the destination match, per-file directory creation, the collision suffix search and partial-file cleanup all become private to Image file emission. `OutputNaming` stops being visible to the rest of the pipeline, so no other module can name a file by a rule of its own. The completion helper and its cleanup behaviour are unchanged.

Both visitors stop naming. The normal-image visitor holds one Image file emission for its traversal, stages every prepared image and finishes when the traversal ends, and `NormalImageNaming` is deleted. A required-cover attempt creates one Image file emission, stages its single prepared image and finishes, so no caller ever chooses singular or numbered naming itself. Normal-image fallback inside the required-cover scope keeps running a fresh normal-image visitor, and so gets a fresh Image file emission. It names its images singularly or numbered exactly as a separate traversal would, which is what ADR-0021 decided. The required-cover scope, its fact fold and the pipeline's public entries (`write_from`, `write_required_cover`, and both visitors' operations) do not change.

The Emitted image tally stays in the pipeline. Each visitor's recording closure records the reported role under its own Image write purpose: the normal-image visitor through `record_normal_image`, and a required-cover attempt through `record_cover`, whatever route the image took, so a GIF-routed cover is tallied as a cover. ADR-0017's two recording methods are unchanged, because each call site still knows its purpose at compile time, and the recording closure is where that knowledge now lives. `emit_prepared_image` is deleted. One pipeline function maps an `EmittedImageRole` onto the tally's destination-free `TallyRole`, and both recording closures call it. ADR-0017 says of that mapping, "That match is the only place production counts anything", and the sentence still holds. The match moves out of the deleted helper into one function rather than being copied into each closure, so production still counts in exactly one place. ADR-0017 therefore needs no status note, and this ADR supersedes nothing. ADR-0007's `EmittedImageRole<'policy>` still carries its routed destination. The destination match moves from the deleted helper into Image file emission and stays exhaustive, so a new role fails to compile rather than silently defaulting to the output directory. ADR-0008's reasoning about Image file emission's direct `std::fs` calls is unchanged: it already created the destination directory before each file, and it still does.

Eight alternatives were rejected:
- Leaving the destination choice in the pipeline and passing a directory per image. "Where a file lands" and "what it is called" would still be decided in two places, and the output directory would still be re-passed to an instance whose base name is already bound.
- Moving tally recording into Image file emission. The glossary's Image file emission entry excludes extraction counts, and emission would then have to know each caller's Image write purpose, which ADR-0017 keeps at the call site.
- Having staging return the roles it completed. A staging call that writes the held-back image and then fails on the next one would have to return "completed before failing" beside its error, which needs a type of its own. A callback records in the same step a file completes, so a failure needs to carry nothing extra.
- Holding the recording callback from construction. The normal-image visitor owns both its Image file emission and its tally, so a callback captured at construction would hold a mutable borrow of the tally for the emission's whole life and contend with the visitor's own access to it. Passing the callback per call keeps each borrow as short as the call.
- Sharing one Image file emission instance across cover attempts and fallback. Fallback runs only when no cover was written, so a shared instance would never number a fallback image after a cover. Sharing would reopen ADR-0021's decision that fallback names its images as a separate traversal would, for no gain.
- Creating each destination once per instance. If a directory disappears mid-document, today's code recreates it before the next file, and creating it once would turn that into a write failure. That is a behaviour change, and it does not belong in a behaviour-preserving refactor.
- Staging that consumes the emission and returns it, so that reuse after an error cannot compile. That is typestate of the kind ADR-0021 rejected for the required-cover scope: it adds a type-level protocol to prevent a mistake that only two in-pipeline callers could make, both of which already abort on the error.
- A single-image shortcut for covers. It would widen the interface for one caller and give that caller back a naming choice that the lookahead already makes. Staging one image and finishing names it singularly with no extra operation.

The work lands in one pull request of three commits, in this order:
1. This ADR and the glossary edit.
2. Image file emission binds the Output placement and chooses each file's directory from its Emitted image role. `emit_prepared_image` shrinks to recording, and the output directory stops being passed per image. The naming mode is still passed in at construction.
3. The singular-versus-numbered lookahead moves into Image file emission. Covers stage and finish through it, `NormalImageNaming` is deleted, the naming mode becomes private, and `emit_prepared_image` is replaced by the role-mapping function. Four naming tests move down and two new ones are added.

Every commit is strictly behaviour-preserving. The files written and their names, the routed-GIF numbering rule, collision suffixes, directory creation, error wording, warnings and their order, the observation stream, the Extraction run outcome and the command-line output are unchanged, and so is the `tests/` suite. A test whose assertion has to change, rather than its setup, is evidence of a behaviour change, not a test to fix. Tests move as they did under ADR-0017: a test moves when its subject is the rule the deepened module now owns, with its assertions unchanged and its setup rewritten to stage hand-built prepared images into a temporary directory. Four move to Image file emission:
- numbering continues past the images that started it;
- numbering follows document position across routed GIFs;
- concurrent image emissions preserve every payload;
- existing output is preserved and uses a compatible collision suffix.

Two are new: a lone staged image is written under the base name alone once emission finishes, and a destination directory does not exist until a file is written to it, including when only a routed GIF is staged. Every other Image write pipeline test stays where it is, as do the partial-file cleanup tests on the completion helper and the naming assertions in the document adapters, EPUB cover extraction, Document extraction, Extraction run intake and the binary tests. They are the regression net for this change.

Out of scope:
- Changing any naming behaviour: the singular and numbered patterns, the routed-GIF ordinal rule, the collision suffix scheme or its attempt limit, the README's naming section, or which document wins unsuffixed names when two share an Output placement, which ADR-0019's extraction order decides.
- Unifying the two visitors' per-image paths by Image write purpose.
- Handing the EPUB adapter its parts the way the DOCX adapter gets them.
- The pipeline's forwarders for the Applicable outcome facts, which ADR-0018 left out of scope.

The glossary change lands with this ADR rather than with the code, following ADR-0017. The Image file emission entry stops describing a per-image responsibility. It now names singular-or-numbered naming, ordinals across every emitted image including routed GIFs, the directory chosen by Emitted image role and collision-free claiming, and it excludes the Image write purpose beside Archive image discovery, conversion and extraction counts. "Naming helper" joins its avoided synonyms. The Output placement entry already gives per-image naming to Image file emission, and the Image write pipeline and Emitted image role entries still read correctly, so no other entry changes. Nothing here becomes public: ADR-0003 still governs the library interface, and every item this change touches stays private to the Image write pipeline. This decision is recorded ahead of the change it governs, in the manner of ADR-0017 through ADR-0021, and 0015 stays vacant for the reason ADR-0016 gives.
