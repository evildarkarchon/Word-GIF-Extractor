# Give the Extraction run a Document extraction seam

The Extraction run hard-wires all three of its collaborators: it passes `FilesystemSearchSurface` and `EpubFileDeclarations` to `select_documents` and calls the `DocumentExtraction` its request built. Every one of the seventeen run tests therefore stages real disk state, including the ones whose subject is pure sequencing — the no-documents short-circuit, the order of document observations around a failure, the transport of opaque warnings — and the outcome accumulator is reached only through temporary ZIPs. The run gains a run-private trait covering exactly the three things it reads from Document extraction: whether EPUB cover extraction is configured, the Applicable outcome facts, and `extract`. `DocumentExtraction` is its production implementation. `run(request, observer)` keeps its signature and becomes the production composition: it unpacks the request and hands the filesystem adapters and the real `DocumentExtraction` to an inner run-private function that takes both selection seams and the extractor. `run_cli`, the intake tests and the presentation tests keep calling `run` unchanged. The trait takes `&mut self` with static dispatch, matching how the run already takes its observer: Document extraction outcomes are not `Clone`, so a test adapter has to hand each scripted outcome out by value, and `&self` would force interior mutability on it for no production benefit. Superseded in part by ADR-0018: the trait and its production implementation are deleted. The seam is now a `&mut impl FnMut(SelectedDocument) -> DocumentExtractionOutcome` closure that covers `extract` alone, and `run` reads cover intent and the Applicable outcome facts from the request's own `DocumentExtraction` and hands both to the inner function as values. The `&mut self` reasoning carries over as the closure being `FnMut`.

Document selection stays real, and that is the decision a later review is most likely to question. A second seam that scripted selection's output and observations outright was considered and rejected. Three run tests — `nested_discovery_failure_precedes_later_progress_and_extraction_in_run_stream`, `recursive_discovery_failure_precedes_later_progress_and_extraction` and `selection_diagnostic_and_completion_precede_extraction_in_one_observation_stream` — pin how selection diagnostics interleave with extraction observations in one stream, and that interleaving is a property of two modules working together; a scripted selection would re-assert its own script. ADR-0008's two seams already have in-memory adapters, so the inner function receives them and passes them through to `select_documents` as the separate `&dyn` parameters ADR-0008 chose over a bundle. Keeping selection real also means `SelectedDocument` needs no test constructor: the run reads only a selected document's path and display name, and a scripted extractor needs nothing more.

The trait covers cover intent and Applicable outcome facts as well as `extract`, rather than having those two arrive at the run as plain values. Lifting them out would copy facts derived from the Image write policy into the run at construction, which is the trade ADR-0006 declined when it kept the Applicable outcome facts chain; the policy stays their single owner. The test adapter honours the same rule from the other side. It wraps a real `DocumentExtraction` built from real policies and delegates both facts to it, so a test that needs conversion to apply builds a policy with conversion, exactly as production does, and only `extract` is scripted. Outcomes are keyed by path and each can be taken once; extracting a path twice, or a path nobody scripted, panics. That turns the request's "consumed exactly once" from a sentence in a doc comment into something a test enforces — ownership already guarantees one move per `SelectedDocument`, but not that the run never extracts the same path twice. Superseded in part by ADR-0018: a value read from Document extraction by `run` at the moment the run begins is not the construction-time copy ADR-0006 declined, so both facts now reach the inner function as plain values, and the Image write policy is still their single owner. The test adapter no longer wraps a real `DocumentExtraction`. Run tests seed cover intent as a boolean and the Applicable outcome facts through `ApplicableOutcomeFacts::fabricated`. The path-keyed outcomes and both panics stay.

Tests fabricate Document extraction outcomes through `#[cfg(test)]` entry points that delegate to the existing private conversions — `from_image_write_result`, `from_image_write_warning` and `from_source` — and build their inputs with `ImageWriteResult::new` and `ImageWriteCounts` literals, as EPUB cover extraction's `CannedAttempts` already does. Direct test constructors for the facts, the warning and the error were rejected. ADR-0007 kept the partition `debug_assert!` in `from_image_write_result` precisely as a tripwire for a fabricated result reaching Document extraction; constructors that skipped the conversion would let the tests be the one place fabricated facts bypass it. Routed through the conversion, the guard checks the tests' own inputs. Production visibility does not change. Superseded in part by ADR-0017: the partition assertion is deleted, so routing fabricated facts through `from_image_write_result` no longer protects anything. `DocumentExtractionFacts::fabricated` now takes an Emitted image tally and Document extraction warnings directly. The warning and error entry points keep the shape decided here.

The trait and its production implementation live in `extraction_run.rs`, owned by the consumer. The run already names Document extraction; putting the trait in `document_extraction.rs` would give that module run vocabulary in its imports, which is the rule ADR-0005 applies — a module's imports should answer what it depends on. The seam is real under the rule ADR-0005 and ADR-0008 both apply: its second adapter is the test adapter. Superseded in part by ADR-0018: with the trait deleted there is no seam type left to place. The closure is a parameter of the inner function, and Document extraction imports nothing from the run.

Sixteen run tests move to the seams with their assertions unchanged; only their setup changes. One stays on disk: `epub_identity_is_consistent_across_normal_and_cover_runs`, the only run test whose subject is the production composition itself — a declared identity flowing through real selection and real extraction into named files. Real document failures remain covered end to end by `run_cli_exits_with_failure_when_a_document_fails` and the integration suite. Two Extraction run presentation tests, `recursive_discovery_diagnostic_suspends_active_scan_spinner` and `document_warning_presentation_adds_one_prefix_and_suspends_extraction_progress`, stop running the whole stack to obtain one observation and feed their observations directly, as their siblings do; this retires the last observer that doubles as a filesystem hook, the pattern ADR-0008 deleted from Document selection's tests. The three `run_cli` tests stay as composition checks.

The change is strictly behaviour-preserving: the observation stream, the outcome, the files written and the command-line output are unchanged, the `tests/` suite is untouched, and a moved test whose assertion has to change is evidence of a behaviour change, not a test to fix. New tests for outcome-classification branches that nothing reaches today — a produced Covers outcome, the mixed-purpose merge — follow in a separate commit, through the run's inner function rather than the accumulator's own interface. Superseded in part by ADR-0017: outcome classification is now tested at the accumulator's own interface, which tests seed with Applicable outcome facts they choose and feed with Emitted image tallies and failures. Classification tests that ran through the inner function moved down, and four run tests stay, each pinning something the run itself hands the fold: its cover intent, the Applicable outcome facts seed, a failed document's partial facts, and every recorded failure. Out of scope: the Document extraction tests' select-one-document helpers, the intake tests that run a DOCX to observe a decision, the EPUB fixture builders in test support, and the manual directory cleanups that predate the temporary-path guard. No `CONTEXT.md` term is added, because the seam carries the existing Document extraction role.

Nothing here becomes public: ADR-0003 still governs the library interface, and the trait, the inner function and the test entry points are all crate-private or narrower. This decision is recorded ahead of the change it governs, in the manner of ADR-0006, ADR-0007 and ADR-0008. The number 0015 is left vacant on purpose: an earlier ADR-0015, written against an older `main`, was withdrawn pending a fresh review of whether its change is still needed.
