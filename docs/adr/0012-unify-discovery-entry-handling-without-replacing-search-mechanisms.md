# Unify Document discovery entry handling without replacing search mechanisms

Document discovery consumes one directory-search operation on the Document search surface, selecting immediate children or recursive search, and uses one loop for entry inspection, supported-document acceptance, progress, and diagnostics. The real adapter retains `std::fs::read_dir` for immediate children and `WalkDir` for recursive search. This decision was accepted ahead of implementation; all three tickets are now implemented as described below.

This supersedes ADR-0008's decision to expose directory listing and recursive traversal as two operations, while preserving its separation of requested-input classification from the adapter. The open equivalence question in that ADR has a concrete counterexample in the locked `walkdir` 2.5.0 implementation: if a requested directory becomes a file after discovery classifies it, `read_dir` reports a failure, whereas `WalkDir` with `min_depth(1)` and `max_depth(1)` excludes the reclassified root and yields nothing. Shallow `WalkDir` also performs entry classification before discovery's inspection and opens direct child directories before discarding work beyond its depth limit. Replacing direct listing with depth-limited traversal would therefore change observations, not merely remove duplicated code.

The shared interface carries entries and failures in encounter order, with depth and failure-path information sufficient to preserve attribution. Entries describe whether the search may descend through them, rather than require immediate-child listing to classify directories. Immediate-child search has no descent; recursive search retains the enumeration-time fact needed to prune a branch when later inspection finds that its directory disappeared or changed kind. Document discovery continues to own followed inspection, broken-link classification, candidate origin, and diagnostic decisions. The adapter owns acquisition mechanics, not document eligibility.

Compatibility requires preserving encounter order, selected documents, link handling, diagnostic attribution and ordering, progress, and continuation after failures. In particular, changing discovery order can change which EPUB survives first-occurrence deduplication. Encounter order means retaining each mechanism's reported order, not introducing sorting or promising that independent filesystem searches return the same order. Only underlying error-detail wording may differ; any other behavioral difference requires a separate decision.

The gain is depth at the existing seam: Document discovery learns one directory-search interface, while inspection and reporting decisions gain locality in one implementation. The real adapter and in-memory adapter keep the seam testable. Selection tests retain their behavioral assertions through that interface, including unreadable-entry continuation, linked roots, stale-branch pruning, and pathless failure attribution. Real-adapter tests cover immediate-child scope, reported order, link paths, and a root replaced after inspection. Tests may adapt how they invoke the interface without weakening their assertions. ADR-0003's narrow library interface remains unchanged.

## Implementation progress

Ticket 01 migrates immediate-child discovery through `DocumentSearchSurface::search` in both adapters. `SearchScope`, `DirectorySearch`, `SearchEntry`, and `SearchFailure` carry ordered acquisition, depth, optional failure paths, and possible descent. Immediate-child acquisition uses direct listing without entry metadata classification; opening failures enter the stream at depth zero with the requested root, and unreadable entries at depth one without a path. Discovery attributes pathless immediate-child failures to the requested directory and continues.

Ticket 02 migrates recursive discovery through `DocumentSearchSurface::search` with `SearchScope::Recursive` and removes the superseded `traverse` operation. The real adapter retains `WalkDir` with the root excluded and no added sorting or depth limit. The in-memory adapter retains its existing declared tree encounter order, linked-path spelling, and failure placement. Its pending items retain the producing directory so pruning discards the whole stale branch, including pathless failures. Discovery still owns followed inspection, candidate acceptance, origin, diagnostics, and pruning decisions. At this stage the immediate-child and recursive consumption loops remained separate until ticket 03. No search-policy or public-interface change is part of this transition.

Ticket 03 consolidates both scopes in one Document discovery consumption loop. Possible descent controls stale-branch pruning; depth and optional failure paths retain nearest-parent attribution, with immediate-child failures falling back to the requested root. Requested-input classification still precedes discovery progress, and candidate origin is recorded at acceptance. Both adapters and their acquisition mechanisms remain unchanged. Existing selection and adapter assertions are retained, with additional complete observation sequences across both scopes and immediate-child first-occurrence EPUB deduplication coverage.
