# Resolve EPUB references once, and carry the Image write purpose on the source

An EPUB whose package document references an image as `../Images/a.png` extracts nothing and exits 0. The `epub` crate joins each manifest href onto the package directory without resolving dot segments, so the reference arrives as `OEBPS/../Images/a.png`. The EPUB resource archive looks that spelling up in the ZIP as it stands, finds no entry, and reports the resource unavailable. The normal-image visitor then drops the warning, because `is_safe_archive_path` calls any name containing `..` unsafe, and an unsafe normal source is a silent skip. The image is lost twice over: once because the resource archive does not resolve the reference, and again because a guard hides the failure.

The EPUB resource archive now resolves each declared reference once, when it seeds its catalog. `.` segments are dropped, a `..` segment removes the segment before it, and a leading `/` resolves against the archive root, as EPUB's container rules define a path-absolute URL. The resolved spelling is then used for the ZIP lookup, the sort key (which absorbs `normalized_sort_path`) and the warning name, so the three can no longer disagree. Lookup tries the resolved spelling first and then its percent-decoded form. It no longer tries the raw unresolved spelling, because an archive entry literally named `OEBPS/../Images/a.png` is not a case worth a third lookup. A reference whose `..` segments climb above the archive root cannot be resolved. It becomes a new unavailability, `ResourceUnavailable::OutsideArchive`, rather than being clamped to the root. Its warning keeps the spelling the crate produced, because there is no resolved spelling to show. Resolution happens in the resource archive rather than in `resolve_resource` alone. The resource archive owns the distinction between document-facing references and Archive resource identity, and resolving only at lookup would leave the sort key and the warning naming a spelling the lookup never used. Two references that resolve to one entry now share an Archive resource identity, which is what that identity already promised.

The unsafe-name rule is deleted with no replacement: `is_safe_archive_path`, `SourceEligibility` and the purpose method that consulted them. It arrived in `9f3b9b5` as a path-traversal guard, but output names came from the document's base name even then, and they still come only from the Output placement. A source name is used for Image format evidence through its extension and as the name in a warning. Neither use decides where a file is written, so the rule could only hide images. A future review should not re-add a traversal guard on source names unless a source name starts reaching an output path. Keeping the rule but warning instead of skipping was rejected, because it would warn about names that are harmless. Keeping it for DOCX alone was rejected for the same reason. With the rule gone, every source a document adapter cannot read warns, and a DOCX entry with an odd name is inspected like any other.

The Image write purpose becomes data on the archive image source. This answers the question ADR-0017 left open about whether the trait should become data. Today the purpose is decided twice. The constructors `ArchiveImageSource::named` and `required_cover` already decide it, through which optional fields are present, and the zero-sized `NormalImages` and `RequiredCover` types decide it again for `discover_image`. The source now carries an enum with two variants: a normal image with its path evidence and optional declared MIME, or a required cover with its declared MIME. Both keep a diagnostic name. `discover_image` matches on the source for the two decisions that differ by purpose: what an unidentified format means, and whether a filtered format warns. `purpose.rs` is deleted, along with the trait, both zero-sized types, `UnidentifiedFormatDecision`, `UnidentifiedFormatAction` and the visitor's purpose field. A runtime purpose passed beside an unchanged source was rejected, because it would let the two disagree. Keeping the trait was rejected because the trait has one generic consumer and its adapters only restate what the constructor already decided. The required-cover constructor stays private to the Image write pipeline, so a source a document adapter hands the normal-image visitor is always a normal image. ADR-0017's two recording methods, `record_normal_image` and `record_cover`, are unchanged: each call site still knows its purpose at compile time when it records into the Emitted image tally.

The work lands in three slices, in this order. First, resolving references changes behaviour: `../` and path-absolute references extract, and an escaping reference is reported unavailable. Its tests are written first, at the EPUB resource archive and through EPUB Document extraction with a fixture EPUB. Until the second slice lands, an escaping reference's warning is still silenced, because its spelling contains `..`. Second, deleting the unsafe-name rule changes behaviour: every unreadable source warns. Its test is the escaping reference's warning, and `purpose/tests.rs`, which tests nothing but the rule, is deleted with it. Third, carrying the purpose on the source is strictly behaviour-preserving. The observation stream, the files written, the command-line output and the `tests/` suite are unchanged by it, and a test whose assertion has to change because of it is evidence of a behaviour change, not a test to fix.

The glossary changes land with this ADR rather than with the code, following ADR-0017. The Image write purpose entry names the role a source is created with, the Archive image discovery entry drops source safety, and the EPUB resource archive entry records that it resolves references once. Nothing here becomes public: ADR-0003 still governs the library interface, and every item this change touches stays crate-private or narrower. This decision is recorded ahead of the change it governs, in the manner of ADR-0017, ADR-0018 and ADR-0019, and 0015 stays vacant for the reason ADR-0016 gives.
