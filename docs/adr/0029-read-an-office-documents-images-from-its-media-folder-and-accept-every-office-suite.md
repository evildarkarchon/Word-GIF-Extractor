# Read an Office document's images from its media folder, and accept every Office suite

The 2026-11-14 audit (M5) showed the DOCX adapter offering every ZIP entry to the Image write pipeline. Word writes an optional `docProps/thumbnail.*`, the preview a file manager shows, and puts it first in ZIP order. It was extracted as a document image, so `thumb.docx`, which holds one picture, wrote `thumb_1.jpg` for the thumbnail and `thumb_2.png` for the picture instead of `thumb.png`. The same audit noted that the adapter was already a generic "images in a ZIP" reader, and that accepting the other Office formats would be mostly an extension table once M5 decided which entries count. Both are decided here.

An Office document's document images are the entries in its Office package's media folder, and nothing else. The extension decides the package and the package decides the folder: `word/media/` for Word, `ppt/media/` for PowerPoint, `xl/media/` for Excel, `visio/media/` for Visio, and `Pictures/` for every OpenDocument file. The adapter skips every other entry before it is read, so a thumbnail, a part's markup, an embedded OLE object or an entry in another suite's folder is not written, not numbered and not warned about. Inside the folder, the bytes still decide, as before: a video in `ppt/media/` identifies no Image format and is passed over by Archive image discovery. The folder comparison ignores ASCII case, because Office Open XML compares part names that way, and it uses the name as the archive spells it, without resolving `.` or `..`.

ADR-0020 says that no source name is grounds for a silent skip. That sentence was written about a guard: a rule that saw a source the adapter meant to read and hid it because of how its name was spelled. This is an eligibility rule, the same kind of decision as Document selection passing over `notes.txt` inside a directory. An entry outside the media folder is not a source the document offers, so there is no failure to report and no warning to give. ADR-0020's rule still holds for every entry the adapter does offer, and it is why an entry whose name cannot be decoded is still offered: the adapter cannot show that it lies outside the folder, and skipping it would lose an image on a guess.

Three narrower rules were considered. Excluding only `docProps/` would fix the reported case and nothing else: LibreOffice's `Thumbnails/thumbnail.png` would be extracted from every OpenDocument file, and any other non-image part with image bytes would still renumber the real ones. Matching any `*/media/*` path, which the audit offered, needs no table, but it would let a Word document's images come from a `ppt/media/` folder that no Word producer writes, and it has no answer for OpenDocument, whose folder is not called `media`. Reading `[Content_Types].xml` and the relationship parts to find the images a document actually references is the precise answer, but it is a parser for each suite where a folder name serves every producer we know of. If a producer that stores images elsewhere turns up, that is the change to make.

The accepted extensions are every ZIP-packaged Office Open XML and OpenDocument format with a media folder: `.docx`, `.docm`, `.dotx`, `.dotm`, `.pptx`, `.pptm`, `.potx`, `.potm`, `.ppsx`, `.ppsm`, `.xlsx`, `.xlsm`, `.xltx`, `.xltm`, `.xlsb`, `.vsdx`, `.vsdm`, `.vstx`, `.vstm`, `.vssx`, `.vssm`, `.odt`, `.ott`, `.odp`, `.otp`, `.ods`, `.ots`, `.odg` and `.otg`. Macro-enabled, template and show variants share their format's layout and so its package. The binary `.xlsb` workbook is included because it is still an Office Open XML package with an `xl/media/` folder. The legacy binary formats (`.doc`, `.ppt`, `.xls`) and the flat OpenDocument XML formats (`.fodt` and the rest) are not ZIP archives and stay unsupported. The table and the folder rule live together in `office_package`, because they are one table. Selection asks the first half and extraction the second, and the package travels on the Selected document between them, since nothing after selection sees the extension again.

The DOCX document kind becomes the Office document kind. `SelectedDocument::Docx` and `SelectedDocx` become `SelectedDocument::Office` and `SelectedOfficeDocument`, the DOCX candidate becomes an Office candidate, and `docx.rs` becomes `office.rs`. Nothing else about selection changes. ADR-0019's single split and single join still put EPUBs first and then Office documents, each in encounter order, and `report.docx` and `report.pptx` in one directory now share an Output placement, so the one encountered first gets the unsuffixed names, exactly as a DOCX and an undeclared EPUB with the same stem already do. ADR-0011's EPUB-only restriction now skips every Office document, and diagnoses each one the user named. ADR-0028's decision to reject an unsupported named input is unchanged, but its wording named the two accepted extensions and the accepted list is now too long to print. The error becomes `Error: Input is not a supported document (such as .docx, .pptx, .xlsx, .odt or .epub) or a directory: …`. It names one extension per suite, so `report.doc` still reads as the wrong kind of file.

This changes behaviour on purpose. A Word document with a preview thumbnail no longer writes it, and its images are numbered from the first media image. A named or discovered `.pptx`, `.xlsx`, `.odt` or any other listed file is now a document, where it was an unsupported input before. Nothing here becomes public: ADR-0003 still governs the library interface, and every item this change touches stays crate-private. The glossary gains Office document and Office package.
