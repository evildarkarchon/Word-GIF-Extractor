# Select a path once, and split Document selection by document kind once

Document discovery yields one candidate per sighting, so a file the user named directly and also reached through a requested directory, or named twice, arrives at Document selection as two candidates that are equal as paths. Selection only ever removed duplicate EPUBs, through Document identity, so a DOCX sighted twice was selected twice and extracted twice. Image file emission never overwrites, so the second pass wrote a full second copy of the document's images under collision suffixes — `book_1.png` beside `book.png`, or `book_1_1.png` through `book_N_1.png` beside a numbered set — with no warning. Selection now treats a path as one candidate. Immediately after discovery, before any eligibility stage, a later sighting whose path equals an earlier one is dropped. The earlier sighting keeps its position, and it counts as requested if any of its sightings was requested, so ADR-0011's diagnostic for a named DOCX in an EPUB-only run still fires when the directory above it was listed first.

"Equal" means equal component by component, as Rust's `Path` equality compares them and as discovery spelled them. Two stronger rules were considered and rejected. Document identity's path key was rejected because it is a rule about books, not files: for an EPUB whose declarations are unusable it is the case-folded file name, and applied to DOCX it would collapse `a/report.docx` and `b/report.docx`, which are different documents. Canonicalisation was rejected because selection cannot do it without a new operation on the Document search surface, ADR-0008's seam, with real-link conformance tests behind it, and because it would make "the same document" depend on how links resolve. The cost is known and accepted: `./dir/x.docx` and `dir/x.docx` remain two candidates.

The rule applies to every document kind, not only DOCX. Seeing the same file twice and finding two files that are the same book are different facts, and only the second is EPUB deduplication's. An EPUB sighted twice therefore no longer enters EPUB filtering and deduplication twice: their totals shrink by one, its declarations are acquired once, and it no longer counts as a removed duplicate EPUB. No existing test pinned the old counts. Limiting the rule to DOCX was considered. It would have left the EPUB progress counts unchanged, but only by continuing to report a file seen twice as a duplicate book, and it would have left the rule that a path is one candidate true for one document kind and not the other.

Dropping a repeat sighting is silent. Discovery's count still counts every sighting, because ADR-0011 keeps that count a fact about the search rather than about the run's policy, and moving the collapse into discovery would make discovery decide something the glossary assigns to selection. A Document selection diagnostic per collapsed path was rejected: the only way to trigger one is to spell the same request twice, which says something about the command line rather than about the user's documents, and a warning line for every `-r dir dir/book.epub` invocation would be noise.

Separately, selection split its candidates by kind three times and joined them back twice. Each EPUB phase partitioned the list, checked the EPUBs, and appended every other document after them, so "EPUBs ahead of other documents after each phase", which ADR-0012 records as preserved behaviour, was a side effect of two re-joins that each had to be written the same way. Selection now collapses repeat sightings, splits once into typed EPUB and DOCX lists, applies the EPUB-only restriction to the DOCX list and filtering and deduplication to the EPUB list, and joins once. The join puts EPUBs first and then other documents, each in encounter order, and that order is now stated where the join is made. It is kept deliberately rather than inherited. Image file emission claims names first come, first served, so extraction order decides which of two documents sharing an Output placement gets the unsuffixed names, and a DOCX and an undeclared EPUB with the same stem in one directory share one. Plain encounter order across kinds was considered and left for a change of its own, so that this refactor does not also move output names. The requested-or-traversed origin leaves the EPUB candidate, which never read it, and stays on the DOCX side, where the EPUB-only restriction reads it.

Out of scope: folding each EPUB phase's per-candidate check closure into the phase that runs it. That would delete the check enums and the diagnostics handle, but it reopens ADR-0012's loop shape and is independent of both changes here. Canonicalising paths is also out of scope, for the reason above.

Only the repeat-sighting collapse changes behaviour. The single split is strictly behaviour-preserving: the observation stream, the selected documents and their order, the files written, and the command-line output are unchanged by it, and a test whose assertion has to change because of it is evidence of a behaviour change, not a test to fix. ADR-0011 stands unchanged; its restriction still runs between discovery and filtering, and the collapse sits before both. ADR-0012 receives a status note pointing here when the split lands, not before, because its "after each phase" wording stays true until then. The glossary changes land with this ADR rather than with the code, following ADR-0017. Nothing here becomes public: ADR-0003 still governs the library interface, and every item this change touches stays private to Document selection. This decision is recorded ahead of the change it governs, in the manner of ADR-0006, ADR-0007, ADR-0008, ADR-0016, ADR-0017 and ADR-0018, and 0015 stays vacant for the reason ADR-0016 gives.
