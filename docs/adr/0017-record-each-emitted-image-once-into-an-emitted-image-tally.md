# Record each emitted image once into an Emitted image tally

Whether an Extraction run produced covers or images, and how many images it converted, skipped or routed, is spelled three times today. The Image write pipeline keeps four counts in `ImageWriteCounts` and a private normal-output flag set through `NormalImageOutput`. Document extraction copies the counts into `EmittedImageTotals` under new names and derives a three-way `DocumentOutputPurpose` from the emitted count and the flag. The outcome accumulator adds the counts up again, merges the purposes, and then reads the merged purpose only as `!= IncludedNormalImages`. A partition `debug_assert!` sits between the first two, and `ExtractionRunOutcome::try_produced` re-validates the result for callers with no run. All of these give way to one **Emitted image tally**. Every emitted image is recorded into it exactly once, under its Image write purpose and a destination-free form of its Emitted image role, through `record_normal_image(role)` or `record_cover(role)`. Tallies combine by addition. The emitted total is derived as normal images plus covers rather than stored. `ImageWriteResult` becomes a tally plus warnings, `DocumentExtractionFacts` becomes a tally plus Document extraction warnings, and the accumulator folds tallies. `finish` classifies a run's output as covers exactly when the run sought covers and no normal image was recorded.

The partition that converted, conversion-skipped and GIF-routed images never together exceed the emitted total stops being an assertion and becomes a property of the type. Today it holds by construction only per image, where `EmittedImageRole` gives each image one role. Every level above holds bare counts and has to trust them or check them: ADR-0006 put the check at the Document extraction seam, and ADR-0007 kept it there as a tripwire for results assembled through `ImageWriteResult::new`. A tally can grow only by recording images, so there is no unchecked total for anything to assemble, and the assertion is deleted rather than moved. `ImageWriteResult::new` stays crate-visible and now takes a tally, so it has nothing left to validate. This also supersedes the third paragraph of ADR-0007, which left `ImageWriteCounts` open because EPUB cover extraction's `CannedAttempts` hand-builds counts to script attempts without opening an EPUB. That seam survives unchanged in purpose: `CannedAttempts` scripts an attempt by recording into a tally. Closing the counts therefore no longer taxes the one place ADR-0005 protects.

What a document's output was for is counted rather than classified. The tally keeps separate normal-image and cover totals, so "covers only" is covers present with no normal images, and "nothing emitted" is both totals at zero. A normal-image boolean beside the counts was rejected for the reason CONTEXT.md already gave: covers-only and nothing-emitted both deny it. Keeping the three-way value was rejected too, because it never excluded the states it was meant to exclude: `IncludedNormalImages` beside an emitted total of zero was as representable as any other combination. With two counts, every combination is a legal state, and "most inclusive wins" is simply what addition does. The pipeline rule that one document never emits both a normal image and a cover also stops carrying weight: a document that did would classify as images, which agrees with the merge.

The tally lives in its own leaf module, `emitted_image_tally`, which imports nothing. The Image write pipeline, Document extraction and the Extraction run observation module import it, so every edge points into it and none can close a cycle. Putting it in the Image write pipeline was rejected because the observation module would then import pipeline vocabulary, which is the edge the fifth paragraph of ADR-0006 refused. Putting it in the observation module was rejected because the pipeline would then depend on run vocabulary. This removes the one reason `DocumentOutputPurpose` existed beside `ExtractionOutputKind`: under ADR-0004's one-way rule, Document extraction could not import the run-level type back. ADR-0004's single observation stream and its outcome placement are otherwise untouched.

Recording takes two methods rather than a purpose value, because every call site knows its purpose at compile time. The normal-image visitor and the required-cover path are each bound to a zero-sized `ImageWritePurpose`, and passing a runtime constant would state something the call site already fixes. This leaves open whether that trait should become data, which is a separate question. The tally owns a four-way role with no destination. The pipeline keeps `EmittedImageRole<'policy>` with its routed destination exactly as ADR-0007 decided, and maps one onto the other in the match that increments counts today. That match is the only place production counts anything, so the mapping replaces it rather than adding to it.

`ExtractionRunOutcome::try_produced` is deleted, superseding the third paragraph of ADR-0006. That paragraph kept a second, validating constructor because the accumulator needed a whole run's worth of state, which a test building one outcome to render could not supply. Once a tally can be built in a few lines, the accumulator is the constructor for callers holding no run. Extraction run presentation's test helper builds its outcome that way, and tests compare outcomes through accessors or against an outcome built the same way. The `ExtractionRunOutcome` and `ProducedOutput` types keep their shape, and presentation reads them exactly as before.

Two decisions of ADR-0016 are superseded. Its fourth paragraph routed fabricated Document extraction facts through `from_image_write_result` so the partition assertion would check the tests' own counts. With the assertion gone, nothing is left for that detour to protect, and `DocumentExtractionFacts` gains a test-only constructor that takes a tally and Document extraction warnings directly. The warning and error fabricators keep ADR-0016's shape, because they exist to keep warning wording and error sealing in one place, which this change does not touch. ADR-0016 also chose, for the follow-up that became its issue 05, to test outcome classification through the run's inner function rather than the accumulator's own interface. Those tests move down. A run test moves when its assertion is about what the outcome says given some facts, and stays when its assertion is about what the run handed the fold. Four stay:
- a failed document's partial facts are folded;
- every failure is recorded;
- the run's cover intent reaches `finish`;
- the Applicable outcome facts seed the fold.

Document extraction's tests follow the same rule. A test whose subject was the translation from pipeline counts is deleted with the translation, and a test that extracts a real document is converted to assert on that document's tally.

The glossary changes land with this ADR rather than with the code, which departs from ADR-0008's convention that a glossary should not define a term the crate does not yet have. That convention exists so a glossary never contradicts the code it names. The departure was chosen so the term is settled before the work that introduces it is planned, and for as long as the two disagree, this ADR is the reference for which one is current. CONTEXT.md gains an Emitted image tally entry. The Document extraction facts entry drops its three-way classification in favour of reading purpose off the tally, and the Emitted image role and Image write pipeline entries name the tally.

The change is strictly behaviour-preserving. The observation stream, the outcome, the files written, the command-line output and the `tests/` suite are unchanged. A test whose assertion has to change for any reason other than a renamed accessor is evidence of a behaviour change, not a test to fix. Out of scope: narrowing the Extraction run's Document extraction seam to per-document extraction alone, which would remove the Applicable outcome facts forwarding and is a separate change; and the Archive resource identity session brand of ADR-0005. Nothing here becomes public: ADR-0003 still governs the library interface, and every item this change adds stays crate-private. This decision is recorded ahead of the change it governs, in the manner of ADR-0006, ADR-0007, ADR-0008 and ADR-0016, and 0015 stays vacant for the reason ADR-0016 gives.
