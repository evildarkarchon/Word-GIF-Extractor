# Keep the library interface narrow and unit tests in-crate

The library exposes four items — `Args`, `run_cli`, `TerminalOutput`, and `Capture` — and every module beneath the crate root stays private, because those four are enough to drive a complete Extraction run and read back everything it wrote to standard output, to standard error, and to the progress display. Moving the unit tests out of the crate so that every test crosses the external seam was considered and rejected on an estimated cost of roughly sixty newly-public internal items. That estimate was a floor: `pub(crate)`, `pub(super)`, and module-public declarations would all have to be widened, which is nearer one hundred and eighty items plus their fields. At either number the interface stops being a promise about what the library does and becomes a namespace listing what it happens to contain, and every internal rename becomes a breaking change.

Unit tests therefore stay inside the crate on purpose. A test whose subject is crate-private belongs beside its subject, and the only way to relocate it is to widen the interface for the test's benefit — the cost the paragraph above rejects. Integration tests cross the four-item seam and nothing else; in-crate tests do not cross it at all. Their crate-privacy is a decision rather than unfinished work, and the correct response to an in-crate test that cannot reach what it needs is to question the test or the module, not to add a `pub`.

As context rather than as a third decision: giving the Extraction run observation enum its own presentation-neutral payload types, so that the stream could cross the boundary without dragging Document selection's progress and diagnostic vocabulary with it, was considered and rejected in favour of internalising the stream entirely. Extraction run presentation moved into the library, which left the stream with no consumer outside the crate, so duplicating the six Document selection types and translating between the two sets bought nothing. That option becomes live again if an external consumer ever needs to observe a run without rendering it.
