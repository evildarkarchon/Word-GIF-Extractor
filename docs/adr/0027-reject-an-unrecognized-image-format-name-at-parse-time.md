# Reject an unrecognized image format name at parse time

The 2026-11-14 audit (M3) showed `--formats` failing open. Extraction run intake kept each token as a string. It warned about any token that named no Image format and dropped it. When no token was recognized, it accepted every format. So `-f pgn` printed one warning, extracted every image, and exited 0: the opposite of the filter that was typed. Intake's comment called the fallback "existing compatibility behavior", but nothing depends on it, and a filter that widens on a typo is not a behaviour worth keeping.

Every `--formats` token must now name an Image format, or the arguments do not parse. The field is typed as Image formats, not strings. A `clap` value parser hands each token to `ImageFormat::from_user_format`, so the accepted spellings stay defined in one place, aliases and case included. A token it does not recognize is a `clap` invalid-value error. That error names the token and the flag and lists the canonical format names. The process prints it to standard error and exits 2, the usage status, before intake runs, so nothing is searched or written. The canonical names are also the parser's possible values, so `--help` lists them. An empty token, as in `png,,jpg` or `-f ""`, is rejected the same way, as a missing value.

One bad token rejects the whole flag, even beside recognized ones. Dropping it and running with the rest would still run a filter the user did not type. Two alternatives were rejected. Failing only when every token was rejected, which the audit offered as the compatible fallback, keeps the silent narrowing. A mirrored `ValueEnum`, as `--convert` uses, would get the same error for free but would have to repeat each alias from `from_user_format`.

`PreRunNotice::IgnoredFormat` and its warning, `Warning: Unrecognized format '…' ignored`, are removed. Intake has nothing left to ignore. The defaulted-input notice is now the only pre-run notice. ADR-0026's stream rule is unchanged: normal output goes to standard output and problems go to standard error. The rejected token is still a problem on standard error, now reported by the parse error rather than by a pre-run notice. The library interface is unchanged as well. `Args` stays public with crate-visible fields, as ADR-0003 asks, and the value parser is private to intake.

This changes behaviour on purpose. A command line that used to run with a warning now stops with exit 2. Every spelling `from_user_format` already accepted still parses.
