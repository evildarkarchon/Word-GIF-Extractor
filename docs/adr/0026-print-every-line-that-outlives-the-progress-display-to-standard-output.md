# Print every line that outlives the progress display to standard output

The 2026-11-14 audit (H3) showed a successful run producing no output at all when standard error was not a terminal: under a pipe, a redirect, a scheduled task or CI. ADR-0013 routed the terminal summary by display state. It finished the live progress display with the summary as its message, and it was printed to standard output only when no display was live. The progress library hides its standard-error target whenever that stream is not a terminal, or when `TERM` is `dumb`: `ProgressDrawTarget::term` returns `ProgressDrawTarget::hidden()`. So the summary was never written anywhere. Phase conclusions vanished the same way: "Found N document(s)", "Found N matching EPUB(s)" and "Removed N duplicate EPUB(s)". The streams were also inconsistent. "No documents found to process." reached standard output, because no display was live, while every other summary went to the display on standard error. A script could not read the result from one place. The capture could not see any of this, because its recording terminal always draws.

The progress display is now decoration only. It carries phase captions, per-document messages and bars, which may disappear when the run moves on. A line meant to stay after the display ends is printed instead: each phase's conclusion and the terminal summary. Presentation clears the display with `finish_and_clear`, which the progress library draws at once, unthrottled, and then prints the line to standard output, on a terminal or not. On a terminal the bar is gone before the line arrives, so nothing redraws over it. The summary no longer depends on display state, since it is printed either way, so the no-documents special case of ADR-0013 needs no rule of its own. Warnings and errors stay on standard error, suspended around the live display as before. That keeps the split pre-run notices already used: normal output to standard output, problems to standard error.

A phase conclusion is still printed only when its phase's display finishes. That keeps each phase's own display in control of it, so a finished observation that arrives out of turn ends nothing. It also leaves conclusions where they always appeared. Non-recursive discovery raises no spinner and so prints no "Found N document(s)". A deduplication phase that skipped nothing clears without a line.

Two alternatives were rejected. Writing the summary to standard error directly, outside the display, would make it survive a redirect. But it would keep the result on the stream scripts treat as diagnostics, and keep the split with "No documents found to process.". Keeping the display route on a terminal and printing only when the target is hidden would make two code paths. The tests could exercise only one at a time, which is how this went unnoticed.

`TerminalOutput` gains a constructor, `captured_without_terminal`. It records both text streams into the same ordered transcript as `captured`, but it draws the progress display to `ProgressDrawTarget::hidden()`, the target production gets off a terminal. A test can then show that everything a user must see reaches a text stream. The library still publishes four items, as ADR-0003 asks, and the new constructor exposes no progress-library type. An integration test also runs the compiled binary with both streams piped. That is the only place the real hidden target, rather than a substitute, can be observed.

This changes behaviour on purpose. A run on a terminal now ends with plain lines on standard output, not a finished bar holding the summary. A run off a terminal now prints the summary and the phase conclusions it used to drop. ADR-0013's transcript design is unchanged. Only its summary routing rule is replaced.
