# Cover-only runs select EPUB documents only

`--cover-only` asks for EPUB cover images. A DOCX has no cover, so it is not work a cover run can do — but until now the run did it anyway, extracting the DOCX's normal images as though no cover flag had been passed. Under a cover-only run, non-EPUB documents are now ineligible: Document selection drops them, they never reach Document extraction, and they are not counted in the run's document total.

This supersedes the fifth paragraph of ADR-0010, which is wrong. That paragraph treated "a cover-only run does not silence a document kind without covers" as a user-visible claim worth preserving, and moved it from a deleted unit test up to a new run-level test. The claim was never intended behaviour; it was the accident that the DOCX dispatch arm ignored a policy it had been handed, and the deleted test had been documenting it rather than guarding it. ADR-0010's actual decision — cover intent carried as `Option<EpubCoverPolicy>`, reaching only the EPUB arm — is unaffected and is what makes this change expressible: there is no cover policy for a DOCX path to ignore, because there is no DOCX path.

Eligibility is decided in Document selection rather than Document extraction. CONTEXT.md already makes selection the part of a run that "decides which discovered documents are eligible to process", and `EpubFilter` had established it as the place eligibility is decided. Deciding in extraction instead would mean selecting a document, announcing it, counting it toward the run total, and then producing nothing from it — a document the run reports as processed and which was never eligible.

Selection is told *that* eligibility is restricted, not *why*. `DocumentSelectionOptions` gains `epub_only: bool` rather than importing `EpubCoverPolicy`, because `document_selection` imports nothing from `document_extraction` today and closing that edge would recreate the mutual dependency ADR-0004 spent a module removing. This is ADR-0005:7's rule applied one level up: a module's imports should answer what it depends on, and selection depends on an eligibility rule, not on a cover feature. It also leaves room for a future non-cover reason to restrict eligibility without renaming anything.

The skip runs between Document discovery and EPUB filtering. Discovery yields supported candidates and owns no filter — CONTEXT.md's Document discovery entry excludes filtering explicitly — so discovery still counts a document it found and this stage removes it. That keeps the discovery count a fact about the search rather than about the run's policy. It is not a phase of its own: the three phases that report progress are the ones that read declarations off disk, and this decision touches nothing.

`SkippedNonEpubInput` is the first Document selection diagnostic that reports a decision rather than a failure to observe. Every existing diagnostic — `MissingInput`, `DocumentDiscoveryFailed`, `UnreadableEpubDeclarations` — says selection could not see something, and non-selection has until now been communicated purely through phase counters, a silence three tests pin deliberately. CONTEXT.md's Document selection diagnostic entry already covered this case in its first clause ("explaining why Document selection skipped a requested input"); the code simply never had a skip that was not a failure.

Only requested inputs are diagnosed. A `.docx` named on the command line produces one warning; a `.docx` found while traversing a directory is dropped in silence, exactly as a filter-rejected EPUB is. Diagnosing every traversal hit was rejected because `--cover-only -r` over a documents folder would print one line per DOCX before the run starts, which is worse than saying nothing; an aggregate count was rejected because it would invent a third diagnostic shape for a case silence already handles. Requested file inputs reach discovery verbatim, so the requested-versus-traversed distinction is an exact comparison rather than a heuristic.

The wording names the rule, not the flag: "this run extracts EPUB documents only". Naming `--cover-only` in the message would assert something no part of the run knows — selection was never told the reason, and presentation renders what the observation carries.

A cover-only run whose inputs are all non-EPUB now returns `NoDocuments` rather than `NoOutput(Covers)`. Teaching the outcome type to distinguish "nothing eligible" from "nothing discovered" was considered and rejected: the diagnostics explain the case for the inputs a user named, which is the case where the distinction would have mattered.
