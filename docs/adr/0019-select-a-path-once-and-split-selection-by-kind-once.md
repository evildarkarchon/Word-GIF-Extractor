# Select a path once, and split Document selection by document kind once

Document discovery yields one candidate per sighting, so a file named directly and reached through a requested directory above it, or named twice, arrives at Document selection as two candidates that are equal as paths. Selection removed repeats only among EPUBs, through Document identity, so a DOCX sighted twice was selected twice, extracted twice, and, because Image file emission never overwrites, written a second time under collision suffixes beside the first copy. An EPUB sighted twice entered filtering and deduplication twice, had its declarations acquired twice, and was reported as a duplicate EPUB of itself. Selection now treats a path as one candidate. Immediately after Document discovery, a later candidate whose path equals an earlier one's is dropped, for every document kind, before the EPUB-only restriction, EPUB filtering and EPUB deduplication. The earlier candidate keeps its position, and it becomes requested if the dropped one was requested, because ADR-0011's diagnostic for a named DOCX skipped by an EPUB-only run depends on knowing that the user named it, even when the directory above it was listed first.

"Equal" means Rust's `Path` equality, component by component, as discovery spelled the paths. Two alternatives were rejected. Document identity's path key, the case-folded file name, would collapse `a/report.docx` and `b/report.docx`, which are two documents; it decides display names and EPUB duplicates, not whether two sightings are one file. Canonicalisation would recognise `./dir/x.docx` and `dir/x.docx` as one, but it needs a new Document search surface operation, which ADR-0008 kept to what discovery observes, and it can fail per path, which would need a diagnostic of its own. The known and accepted limit is that two spellings of one path stay two candidates. The collapse is silent: it adds no Extraction run observation, no Document selection diagnostic and no wording, and it is not a progress phase, because like the EPUB-only restriction of ADR-0011 it reads no declarations and has nothing to report. Discovery's count still counts every sighting, because it is a fact about the search rather than about the run's policy (ADR-0011).

The defect was possible because selection split its candidates by document kind three times and joined them back twice. The EPUB-only restriction partitioned, diagnosed named DOCX and kept the EPUBs; EPUB filtering partitioned, checked the EPUBs and appended every other document after them; EPUB deduplication partitioned again and appended again. Deduplication only ever saw the EPUB side, so there was no step at which a DOCX could be recognised as seen before. After the collapse, selection splits the candidates once, into a typed list of EPUB candidates and a typed list of DOCX candidates. The EPUB-only restriction runs over the DOCX list, filtering and deduplication over the EPUB list, and one join produces the Selected documents. `partition_epubs` and both re-join blocks are deleted. The EPUB candidate stops carrying the requested-or-traversed origin, which nothing on that side reads; the DOCX side keeps it for the EPUB-only restriction.

The order the join produces is the order the re-joins happened to produce: EPUBs first, then other documents, each in encounter order. ADR-0012 called it preserved behaviour without stating it anywhere. It is now stated in a comment at the join, and it is kept rather than changed to plain encounter order across kinds because extraction order decides which of two documents sharing an Output placement receives the unsuffixed output names. Changing it would rename files users already have, and that is a decision of its own.

Unchanged: the three phases' progress observations and their ordering, the per-EPUB check closures and the lifecycle's ownership of the EPUB check loop (ADR-0012), the per-fact diagnostic methods (ADR-0009), `epub_only` as a plain flag (ADR-0011), Document identity, and Output placement construction. The split is landed as a strictly behaviour-preserving refactor after the fix, preceded by a characterization test of the order, so that any existing assertion it changes reads as evidence of a behaviour change rather than a test to fix.

Out of scope:
- folding each EPUB phase's per-candidate check closure into the phase that runs it, deleting `EpubFilterCheck`, `EpubDeduplicationCheck` and `EpubDeclarationDiagnostics`, which reopens ADR-0012 and is independent of this change;
- canonicalising paths to recognise two spellings of one path as one candidate;
- changing the output order to plain encounter order across kinds;
- any warning or count for a collapsed sighting;
- the unrelated defect from the 2026-10-05 review, that an EPUB XHTML resource with inline SVG near its start is probably emitted as SVG.

Nothing here becomes public: ADR-0003 still governs the library interface, and every item this change touches stays private to Document selection. This decision is recorded ahead of the change it governs, in the manner of ADR-0017 and ADR-0018, together with the `GLOSSARY.md` entries for Document selection and Document discovery. ADR-0012 receives a status note pointing here when the split lands, not before: its account of EPUBs placed ahead of other documents after each phase stays true until the per-phase re-joins are gone.
