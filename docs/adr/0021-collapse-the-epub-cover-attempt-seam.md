# Collapse the EPUB cover attempt seam into one concrete EPUB cover extraction

ADR-0005 made EPUB cover extraction reach the archive and the Image write pipeline through an injected `CoverAttempts` trait, and made it generic over the Archive resource identity so its tests could pass a plain integer instead of opening an archive. That generic now costs more than it buys. Every catalog entry is copied twice on its way to a cover attempt. The EPUB adapter clones each `EpubResource` into an `EpubImagePlan`, because `resources()` borrows the EPUB resource archive session immutably while `acquire` borrows it mutably. It then clones the id and manifest path again into a `CoverCandidate`. One number is spelled three times along the way: the resource key's index, the plan index and the candidate's `position`. The production adapter documents a panic for a `position` that does not address its plan. The cover decision itself is about forty lines. To reach it a caller has to learn a two-method trait, a candidate type, a type parameter and four arguments, and the decision's own module folds Image write pipeline facts by hand, writing the same prepend-on-error block twice. EPUB cover extraction becomes one concrete function over the real session and the real pipeline, and the trait, its two adapters and the generic are deleted. This supersedes ADR-0005.

ADR-0005's reason for the generic was that `ArchiveResourceIdentity` is branded and can be obtained only by opening an archive, which opens a file, so every test of ordering, exclusion and retry would have to write a ZIP and read files back. Half of that no longer holds. The EPUB resource archive's own tests already open real branded sessions from a temporary ZIP and hand-built `EpubResourceDeclaration`s, with no output directory. A test of a cover decision therefore needs a real session, which is cheap, and a temporary output directory, which every test that writes images already has. Each of the ten behaviours the `CannedAttempts` fake scripted can be produced with real inputs:
- a read-failure retry, by corrupting a stored payload, as the EPUB adapter's tests already do;
- an already-attempted identity, by percent-encoded aliases of one entry;
- an emission failure, by a file standing where the GIF destination or the output directory should be, as Document extraction's partial-failure test already does.

The singular-versus-numbered lookahead makes "a routed GIF, then a normal image that fails" reachable in that order. Those tests keep their assertions and change their setup. Where an assertion was a recorded call list, the same fact is now observed through the warnings and the files written. For example, "fallback excluded the attempted identity" becomes "the aliased cover payload was not also written as a normal image". The cost is accepted: retry-then-fatal sequencing can only be tested with a fixture EPUB, and those tests write files.

Three alternatives were rejected:
- Keeping the trait and removing only the copies. That would leave a seam whose second adapter is a fake for decisions that can now be tested through the real one.
- Splitting EPUB cover extraction into a pure ordering function, with the retry, completion and fallback loop moved into the EPUB adapter. The ordering tests would have been purer, but the glossary gives EPUB cover extraction ordering, retry, identity exclusion and fallback together, and the split would scatter one responsibility over two files.
- Two closures in place of the trait. ADR-0005 rejected them because both operations need a mutable borrow of one session, and that objection still holds. With no seam there is nothing for either form to stand in for.

The EPUB resource archive lends its catalog and its payloads separately. `EpubResourceArchive::open` hands its callback the ordered catalog and a payload reader as two parameters, rather than one session that is borrowed whole either way. `acquire` takes a catalog entry rather than a `ResourceKey`. The key stays branded but becomes private to the entry, so an entry from another session still cannot be acquired. `ResourcePayload` is deleted. Its brand field was never read, and the reader's higher-ranked lifetime already keeps a payload from escaping its consumer. With the catalog borrowable while payloads are acquired, cover extraction and normal-image traversal read catalog entries directly, and `EpubImagePlan`, `from_catalog`, `cover_candidates`, `position` and its panic clause are deleted. ADR-0020's resolution, ordering and Archive resource identity rules are unchanged.

The Image write pipeline accumulates the facts of a cover attempt sequence, as `write_from` already does for a normal-image traversal. `write_required_cover` becomes a scoped entry that hands its caller a cover visitor with three operations:
- an attempt, which takes a cover's source facts and payload reader and returns a fact-free `RequiredCoverDisposition`, retry or completed;
- unreadable, which records why a cover's payload could not be acquired and always means retry;
- fallback, which runs a traversal against a fresh `ArchiveImageVisitor`, with its own singular-versus-numbered naming exactly as a separate `write_from` has today, and appends its facts after the cover attempts' facts.

The scope returns one `ImageWriteOutcome`, and an emission failure anywhere keeps every fact recorded before it. `RequiredCoverWriteOutcome` is renamed `RequiredCoverDisposition` because it no longer carries facts, and in this crate an outcome is a terminal result that does. `required_cover_unavailable` is deleted in favour of the visitor's unreadable operation, which is how normal images already report the same fact. `ImageWriteResult::append` and `ImageWriteFailure::prepend` lose their only consumer outside the pipeline and become private to it, since the scope still combines cover facts with fallback facts. Typestate that would stop an attempt after fallback or after a completed disposition was rejected. It adds a type and a lifetime to prevent a mistake only one caller could make, and that caller's tests pin the order. ADR-0017's `record_normal_image` and `record_cover` are unchanged: each call site still knows its Image write purpose at compile time. So is ADR-0020's purpose carried on the archive image source.

EPUB cover extraction takes `EpubCoverPolicy` rather than the flattened boolean. ADR-0005 flattened it so the module would import no Document extraction type, so that its imports would answer what cover extraction depends on. A module that works directly against the session and the pipeline has already given up that minimalism, and the flattening was the one place the policy had to be translated. Normal-image traversal moves out of the EPUB adapter into a sibling module, `epub/normal_images.rs`, which visits every catalog entry except a given set of Archive resource identities. The EPUB adapter calls it for a run seeking no covers, and EPUB cover extraction calls it for fallback. This keeps the dependency direction ADR-0005 cared about: the child calls a sibling, never its parent. The EPUB adapter is left acquiring declarations, opening the session and choosing a path by policy.

The work lands in three slices, in this order:
1. The EPUB resource archive lends its catalog and payloads separately, and `ResourcePayload` and `EpubImagePlan` are deleted. `EpubCoverAttempts` indexes the catalog directly, and `position` survives until the third slice.
2. Normal-image traversal moves to `epub/normal_images.rs`. This is a pure move.
3. The pipeline's scoped cover entry lands with the concrete EPUB cover extraction and its rewritten tests. `CoverAttempts`, `EpubCoverAttempts`, `CannedAttempts`, `RecordedAttempt`, the identity type parameter, `required_cover_unavailable` and the boolean flattening are deleted. This slice is atomic, because the tests change with the interface they exercise.

Every slice is strictly behaviour-preserving. The observation stream, the files written, the warnings and their order, the command-line output and the `tests/` suite are unchanged. A test whose assertion has to change, rather than its setup, is evidence of a behaviour change, not a test to fix.

Out of scope:
- The warning that names an unavailable resource twice: "Could not read archive resource 'X': EPUB resource not found: X". `ResourceUnavailable`'s wording embeds the manifest path that the Document extraction warning already prefixes. Fixing it changes user-visible output, so it is a change of its own.
- Pruning the end-to-end tests in Document extraction and the EPUB adapter that overlap the rewritten cover extraction tests or the EPUB resource archive's own tests.
- Retaining EPUB declarations from Document selection to Document extraction (ADR-0001, ADR-0002).

`GLOSSARY.md` does not change. Its EPUB cover extraction entry already names ordering, retry, identity exclusion and fallback, and still excludes archive reading mechanics and Image file emission. Its Cover candidate entry still describes a catalog entry under consideration rather than the payload it resolves to. The ordered fold of pipeline facts was recorded only in ADR-0005, and this ADR moves it into the pipeline. Nothing here becomes public: ADR-0003 still governs the library interface, and every item this change touches stays crate-private or narrower. ADR-0005 receives a status note pointing here when the third slice lands, not before, so no ADR describes a design the code does not yet have. This decision is recorded ahead of the change it governs, in the manner of ADR-0017 through ADR-0020, and 0015 stays vacant for the reason ADR-0016 gives.
