## Key Findings

- DOCX extraction currently filters ZIP entries by archive entry extension before reading file bytes in `src/docx.rs`.
- `ImageToExtract` currently stores only ZIP index and extension, so detected format can replace the stored extension after reading bytes.
- Conversion and GIF routing already key off `image.extension`, so using detected format there will keep downstream behavior consistent.
- EPUB extraction also filters by metadata/path/MIME, but this OpenSpec change specifically targets ZIP-entry binary detection in the DOCX pipeline; keep EPUB behavior unchanged unless implementation uncovers shared helper needs.
- Requirement mismatch: task 1.4 says read first 12 bytes, but the spec requires EMF detection by finding `EMF` in the first 44 bytes. Implementation should treat the spec as authoritative by reading enough header bytes for EMF while documenting the exception.

## Implementation Plan

1. Add a focused magic detection module.
   - Create `src/magic.rs` and add `mod magic;` in `src/main.rs`.
   - Define constants/pattern checks for PNG, JPG, GIF, BMP, TIFF little-endian, TIFF big-endian, WebP, ICO, WMF, and EMF.
   - Implement `pub fn detect_image_format(data: &[u8]) -> Option<&'static str>` with a doc comment.
   - Check SVG by trimming leading ASCII whitespace/BOM where safe, then matching `<?xml` or `<svg` prefixes case-insensitively enough for common SVGs.
   - Read/inspect only the provided byte slice; callers will pass full data after ZIP read. Internally use at most the needed prefix, with EMF checking the first 44 bytes per spec.

2. Integrate detection into DOCX extraction.
   - In `src/docx.rs`, change the first archive scan from extension-based inclusion to safe-path collection of candidate ZIP entries, keeping original extension as optional fallback.
   - Read each candidate entry before filtering.
   - Call `magic::detect_image_format(&data)`.
   - Use detected format for `allowed_extensions` filtering, output extension, conversion source extension, and GIF routing.
   - If detection returns `None`, fall back to the original lowercased extension only if present, and emit a warning before applying the existing allowed-format filter.
   - Preserve current output naming via `get_unique_output_path` and current count behavior.

3. Keep changes minimal around common structs.
   - Either update `ImageToExtract` to include `Option<String>` fallback extension if still useful, or remove its use from DOCX if a local struct is clearer.
   - Do not change CLI parsing, supported extension normalization, EPUB processing, conversion APIs, or output directory rules unless required by compile errors.

4. Add tests.
   - Add unit tests in `src/magic.rs` for PNG, JPG, GIF, BMP, TIFF LE/BE, WebP, ICO, WMF, EMF, SVG, unknown data, and short data.
   - Add a unit-testable fallback helper if practical, otherwise cover fallback through DOCX extraction tests.
   - Add an integration test under `tests/` that builds a minimal ZIP named `.docx` containing `word/media/image1.bin` with PNG magic bytes, runs the CLI or DOCX processor with `-f png`, and asserts the output file uses `.png`.

5. Mark OpenSpec tasks complete as implementation progresses.
